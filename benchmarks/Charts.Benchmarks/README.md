## C4-08 CI regression entry point

`scripts/Invoke-ChartsPerformanceGate.ps1 -BaselineSourceDirectory <independent-base-checkout> -OutputDirectory <new-path>` builds both harnesses, runs all seven C4 mechanism regressions and the fixed five-sample headless corpus, drives an actual native window, then invokes the independent guard. The Linux wrapper uses Xvfb in hosted CI. Windows uses `-NativeMode DesktopSynthetic`. PR jobs build the base product in a separate checkout using exactly the candidate native harness source; non-PR jobs identify the paired run as a same-version control. The baseline product is never replaced by candidate sources.

`scripts/charts-ci-performance-policy.json` versions the hosted runaway timing/allocation limits, paired regression ratios/noise allowances and exact native pixel-difference policy. The policy snapshot and source contracts are captured before measurement; candidates never update their own baseline or thresholds. Existing proposed fixed-hardware frame/present targets remain unchanged. `Test-ChartsRegressionGate.ps1` recomputes percentiles from raw ticks, authenticates immutable evidence, uses the existing headless integrity guard, checks static mechanism contracts and independently decodes native PNGs/data/hit/trace receipts. Missing, malformed, canceled, late and failed work cannot disappear from a successful run.

The native protocol explicitly disables tiered compilation in its hashed runtime configuration and verifies the AppContext value and environment overrides in both processes. Protocol v2 retains the same numeric policy, sample count and warmups as v1. It follows a preserved same-source control failure with different slow-to-fast layout transition positions; the cause was not proven. Results under this controlled benchmark configuration do not qualify an application's default JIT behavior.

Each producer is supervised without retries; stdout/stderr stream to disk, partial snapshots survive termination, every native request has a correlation ID, and paired pixel differences are saved. CI uploads raw JSON, datasets, PNGs/diffs, JSONL traces, policy, source/payload manifests, logs, exit/timeout receipts and guard results even on failure. `checksums.json` covers the completed evidence directory. These are hosted regression checks, not compositor-present/GPU, actual process-memory, long-soak or official-reference qualification.

## C4-07 multi-chart scheduling and background numeric layout

Run `--multichart-background-layout-regression --output <new-path>/raw.json`. The fixed fixture contains four charts, 2,048 rows per series, smooth lines and two-member smooth area stacks, including data gaps. Before the first measurement, its gates are:

- A 1,000-request storm coalesces and every queued chart receives one refresh dispatch. Dispatch counters describe invalidation turns, not presented frames. Reentrant FIFO fairness and background cancellation are additionally covered by headless tests.
- Every admitted current worker publishes. Worker thread IDs differ from the UI thread. All ordered numerical path parts, source ordinals, controls and fractions have exactly the same IEEE754 fingerprint as the synchronous path. Original point hits retain their source index, point and stable identity.
- Three unpumped viewport changes reject the first two results and publish only the latest, matching synchronous geometry. Ancestor hiding stops automatic refresh/data preparation and clears registered local cache estimates; showing prepares current source data.
- The shared logical local-resource estimate respects 128 KiB, then immediately respects 4 KiB; process trim clears every chart's local ledger. A zero payload budget rejects before numeric capture while synchronous business paths remain available. Observed reservations respect 32 MiB/four admitted jobs/two running workers; detach drains queues, payload reservations and resources.

The report saves raw scalar budget observations, per-chart counters, exact numerical path hashes and original hit receipts. Capture-thread allocation and elapsed ticks are observations only. It does not measure rendering/present latency, actual process/native/GPU bytes or long-soak retention. UI mapping, projection, axis/text/native geometry and unsupported layouts remain synchronous. These gates add to the previous regression fixtures without weakening their thresholds.

## C4-06 render reuse, allocation and local budgets

Run `--render-resource-budget-regression --output <new-path>/raw.json`. Three fixtures enforce gates declared before the first measurement:

- A 20,000-point linear line, five warmups and twenty samples per mode: cached rendering performs no source/view/series/axis-text/axis-pen rebuild or projection. Each cached sample allocates at most 2 MiB, and total cached thread allocation is at most half of the disabled-cache control. Forty view/long-label revisions exercise a 16 KiB budget. Every sampled five-layer sum equals `EstimatedBytes` and remains within `BudgetBytes`; trim, zero budget and detach remove local entries. Paint mutation, trim and disabled drawing retain the same canonical vector-leaf fingerprint and original point hit.
- Explicit compaction packs 2,048 singleton pages into eight pages, copies exactly 2,048 payload and mapped rows, performs zero new mappings or business getter reads, increments one buffer/series version, and preserves all current/historical original records. The second compaction is a no-op. It is a deliberate O(N) operation with temporary old/new storage, not an automatic append-time memory bound.
- Three thousand independently positioned segment queries visit 6,000 distinct source endpoints. Thirty fixed checkpoints verify at most 4,096 retained projected endpoints per series, and actual eviction must occur. A deterministic private text-helper draw fills interaction resources; all five local layers must be populated, then clear under trim/zero budget while original segment pairs remain correct. An oversized literal bypasses admission. This helper is not a routed Tooltip test; native Demo checks cover the actual product input route separately.

The drawing fingerprint flattens effective transforms, clips, opacity, glyphs, paints, geometry strings and bounds. Opaque native path commands are not independently decoded; native PNG and original-data oracles are separate. Five-layer estimates exclude shared source/series/context caches, prepared shaped paths, caller objects, font-manager caches and native/GPU allocations. Four short process snapshots record managed estimates, latest-GC heap values, total allocations/GC counts and available OS private/working-set counters without forced GC. OS peak working set is process-lifetime, not an exact per-fixture peak. Missing OS counters and native/GPU bytes are null; private-minus-managed is not native memory. No timing, frame/present, sustained throughput or long-soak qualification is inferred.

This console uses Avalonia.Headless and public Charts APIs. It records a host source `ToArray` snapshot, source assignment, initial/cached scene getters, `DrawingGroup` render recording, hit queries, thread allocations and process memory. Instrumented source enumeration is nested inside scene preparation and must not be added to it.

`renderRecord` is **not** frame-pipeline, compositor render completion, present or FPS. Those values remain null; native/present and official-reference comparisons are blocked. `producerPassed`/the independent guard only describe diagnostic completion and raw-data consistency. No proposed C4 latency budget is evaluated, and small samples are not formal performance acceptance.

The C4-05 incremental streaming regression runs independently:

```powershell
dotnet benchmarks/Charts.Benchmarks/bin/Release/net10.0/Charts.Benchmarks.dll --incremental-streaming-regression --output <new-output.json>
```

Its gates are declared before measurement. Four object-mapped `LineSeries` retain 250,000 rows each in `ChartDataBuffer<T>`. After the initial million-row snapshot, one `ChartStreamingSession<T>` accepts 120 batches of 500 rows (125 per series). Each accepted batch is flushed to its UI source callback before snapshots are mapped. The fixed input represents 500 samples per virtual 50 ms; it runs accelerated and does not demonstrate actual 10,000 samples/s pacing. Every revision records raw source/copy/mapping counters, versions, elapsed ticks and current-thread bytes. Buffer copies and mapped rows must each equal the 500 new rows. UI source commit and snapshot mapping have separate counter intervals: mapping must independently read exactly 500 X and Y getters, while the complete interval permits at most 1500 reads of each to include observer-path traversal on new and evicted rows. Exact mapping getter counts prevent deferred work from escaping into the later oracle. Buffer-copy counts exclude the session's bounded input/coalescing arrays. New directory entry counts are recorded separately; temporary slice traversal remains O(P) and is not fully instrumented. Producer row construction and independent oracles occur outside measured intervals. Timing includes UI dispatch, reflection counter reads and snapshot mapping; it has no latency or allocation threshold.

The independent original-row oracle checks all final million rows and all retained initial million rows for item reference, stable ID, current source ordinal, raw coordinates and version. The deterministic generator is `charts-c405-integer-triangle-v1`: for series `s` and zero-based sequence `q`, `X=q/2500`, `phase=q%1024`, `triangle=phase<512?phase:1024-phase`, `noise=((q*1103515245+12345)&511)-255`, `Y=(triangle*32+noise)/256+s*3`, and ID `series-{s}/sample-{q}`. Each hash appends, for every current ordinal in order, little-endian Int32 source ordinal, little-endian IEEE754 Int64 X and Y, UTF-8 ID, then a zero byte. The initial sequences are 0 through 249999 and final sequences are 15000 through 264999. A separate small fixture saves all expected and actual raw rows across append, insert, replacement, removal, capacity eviction and clear, then rechecks every retained historical snapshot.

Page summaries are measured after mapping in a separate `extremaWork` interval. Every revision saves actual and independently recomputed full-source valid counts, extrema and ascending/descending flags for both axes. Summary row visits must be at most 2548: the 500 new rows plus up to two 256-row boundaries for each of four streams. Whole-page summary merge and temporary directory traversal still scale with page count; the new-directory-entry counter does not measure all of that O(P) work. The initial full summary scan remains in the cold receipt. Oracle scans are outside all measured intervals.

A controlled paused fixture saves every produced and committed sample plus the actual callback grouping. At most two accepted batches may be pending, including an in-flight UI batch. A third `TryAppend` explicitly rejects and counts its samples; one `AppendAsync` writer may wait for capacity, while additional waiting writers fail explicitly. Resume must preserve all accepted sample order and coalesce the two queued batches; cancel must account for every accepted uncommitted sample, and a late posted callback must apply none of them. `accepted = committed + pending + canceled + faulted`; the append-only window additionally requires `initial + committed = retained + evicted`. Rejected samples count denied attempts, so retries of one unique sample can increment rejection more than once; only this fixture's no-retry ledger equates unique produced samples to accepted plus rejected. Cancellation before acceptance is separate from accepted cancellation. An arbitrary apply delegate is not transactional: a throwing delegate may already have side effects, is reported as failed and is not silently retried.

A fourth fixture attaches an actual four-series chart to a Headless window and records twelve source revisions followed by `DrawingGroup` rendering. It uses numeric axes, unstacked linear lines with `SamplingMode=None`, a trailing window of 512 integer sample-X units, and the same Y/ID generator above. Its X is `q`, and its final sequences are 1500 through 251499. The single session applies all four buffers inside `chart.DeferDataUpdates()`. Each measured source/render interval requires exactly 500 copied/mapped buffer rows, at most 2548 summary row visits, 1–8192 recorded projected points, at most 8 view builds and one deferred chart commit/UI callback. These are fixture-specific work gates. First lazy selection identity construction is saved separately as cold work; each revision then verifies original hits, rebased surviving selection, removed evicted selection, exact following/paused ranges and the final million-row source identity oracle. An explicit viewport write after revision 3 pauses following through revision 6, and enabling follow again must catch up. Navigation and independent identity queries occur outside source/render work intervals and retain their raw results.

These diagnostics qualify bounded reception, UI source commits, structural sharing, incremental mapping/summaries and the declared attached-chart work counters.
