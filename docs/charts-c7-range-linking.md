# C7-01 专业范围选择与多图联动

更新日期：2026-10-24。候选 v3 已通过 Windows 与 Linux WSLg 的冻结软件验证；C7 整阶段出口及完整官方等价验收继续开放。

本批继续专业图族的共享能力集成：为 EngineeringChartBase 与 AnalysisChartBase 增加原始数据多选、当前布局范围选择和业务 ID 联动；Demo 与编译绑定 Usage 同时接入。地图图层、关系图节点和边保留各自的身份域。该能力使用真实图元及其原始成员，不把不同专业图族转换成虚构的共同数据坐标。

## 选择和范围契约

| API | 行为 |
| --- | --- |
| `SelectedDataKeys` | TwoWay 请求状态；替换列表触发更新。显式 ID 按值匹配，隐式来源按对象引用匹配。地图使用带图层作用域的 MapGlyphKey，关系图使用区分节点/边的 RelationGlyphKey。未知请求保留，等待相应数据重新出现。 |
| `SelectedData` / `GetSelectedData()` | 返回当前可见且有效的原始 ChartDataPoint。显式键只返回匹配成员；范围或聚合图元点击可选中其全部原始成员。整图元高亮不表示它的所有成员都已选中。隐藏、禁用或卸载时释放公开来源引用，保留请求状态。重新出现后只发布当前来源对象。 |
| `DataSelectionRange` / `SelectDataRange(Rect?)` | 当前绘图区从左上向右下递增的 0～1 布局比例。按可见真实图元的轴对齐包围盒相交选择，包含相交图元的完整原始成员；零宽或高边界膨胀 0.5 DIP。不执行圆弧、多边形孔洞或连线路径的精确框选。它是选择范围，不是数据轴或地图经纬度视口。 |
| `ClearDataSelection()` | 清除范围和多选请求，独立于既有 SelectedIndex/SelectedPoint。显式点击、Enter/Space 接入业务选择；ResetViewport 同时清除当前选择和范围。直接修改 SelectedIndex 不隐式改写独立多选绑定。 |
| `DataSelectionChanged` | 在当前来源和范围一致后通知；业务回调提出的新状态优先，过期帧不再向外联动。 |
| `ChartDataRangeSelector` | 组合现有双手柄选择器，复用指针拖动、键盘及端点辅助语义。X 从左向右，Y 从上向下；横纵选择器分别保留另一个方向的范围。挂载时已有图表范围优先；图表没有范围时才使用选择器离线设置的非默认范围。MinimumSpan 不改写外部传入的更窄范围。 |

选择及联动 API 在 Avalonia UI 线程调用。选择高亮由被动前景层绘制，位于 PlotAreaContent 和永久标签上方、临时 Tooltip/Trackball 下方，不抢占命中或 Tab。稳定查询复用缓存结果；移动读数不重新枚举整个业务来源。

## 联动契约

`ChartDataSynchronizationGroup.Add` 注册专业图表和可选业务键选择器。不同图族可以共享业务 ID，而不要求来源顺序、局部索引或聚合方式一致。注册本身不选定初始来源；需要初次复制时显式调用 SynchronizeFrom。默认只联动业务选择。

范围和工程图视口联动分别通过 SynchronizeRange / SynchronizeViewport 开启，并要求成员显式给出相同的非空 layoutDomain。只有调用方确认布局可比较时才复制比例范围或 Zoom/Pan；Analysis 图族没有工程视口，不接收虚构的缩放轴。不同地图投影、不同时间布局或不同分类排序不能仅因都是专业图就共用此域。

组成员的图表使用弱引用；调用方传入的 keySelector 和 layoutDomain 由组持有，委托捕获图表或 VM 时仍会保留该对象。隐藏、禁用、卸载或移除时停止监听和接收变化，Dispose 释放订阅。重新挂载不会自动把旧选择广播给其他成员。来源替换、排序和聚合变化后重新映射真实对象；目标没有的业务 ID 不生成虚假选中数据。同步回调改变业务状态时保留较新的意图；矛盾的循环绑定在有限次数后明确失败。组不替换 ItemsSource 或执行交叉筛选，业务筛选可在应用事件中实现。

业务联动匹配当前真实绘图帧中保留的全部成员，包括被本地视口裁剪的图元；公开 SelectedData 仍只报告当前可见选择。这样不同成员的平移不会把仍有真实图元的业务选择意外当作清除。映射不扫描未绘制的原始来源；某个投影根本没有生成相应图元时，不能把缺失标记当作已验证的选中对象。

## Demo 和导出组合

Demo 新增“专业图族 · 范围选择、业务 ID 联动与完整呈现”，包括 Funnel、Mosaic、Strip 与 SeatMap，展示局部范围条、双向业务选择、清除、来源替换、VM 切换、主题和生命周期。Usage 使用编译绑定验证选中键和范围。同布局域的范围和视口联动由专项测试验证，异构四图看板没有将不可比较的布局强行共用范围。

永久 PlotAreaContent、共享图例、数据标签和选中高亮进入 PNG/JPEG 同步及异步导出；临时范围框、Tooltip 和 Trackball 排除。新增组合场景使用真实层级图数据动画：暂停后换主题、替换并重排相同 ID 的来源，再验证永久模板、当前原始选择和导出帧。绘图区投影使用当前动画帧的实际 Zoom/Pan，保持 ProjectLayout/UnprojectLayout 与显示几何一致。关系图后台布局继续遵循自身布局契约，不将后台布局当作动画功能。

默认专业 Trackball 线和标记加入相反明暗色的轮廓，以改善白色图元上的白色描边可见性；显式笔刷继续由调用方决定。此结果不等于所有自定义填充、透明度和抗锯齿边缘都达到 7:1 对比度。

## 修正记录与候选身份

本批回归修复了隐藏选择的重复排队、清理和单点输入回调中的旧状态覆盖、连续视口操作覆盖新意图、视口外业务键更换遗漏事件，以及来源移除全部原始成员后遗漏清除通知。默认没有选择请求时跳过成员遍历；聚合成员采用延迟映射，避免为查询一项而复制完整聚合。

原生 Usage 的超时定位到关系图错误状态循环：只读 LayoutError 通知触发通用数据失效，新的选择刷新立即重建同一错误来源，又发布新的错误对象。现在派生图族的只读状态输出不再反过来驱动源重建；九种关系图模式验证错误状态稳定，并在同一个控件上恢复有效来源。

暂停动画换主题的原生探针显示实际 PlotArea 和几何没有改变，进度却重置为零。最终原因是私有映射系列把继承主题的属性通知交给通用 Changed，工程根误当作业务数据变化。现在属性通知只更新外观帧，真实映射、来源和 INPC 变化继续触发数据失效；层级布局只由实际布局输入或 PlotArea 变化重建。最终原生暂停进度在主题前后精确相同，真实来源替换仍可重新建立过渡。

旧开发失败和超时均保留，包括测试夹具不符合通用 IdPath 唯一性约束、纵向路由输入整数像素量化、测试调用了不可用的 Dispatcher 参数，以及暂时未完成的并行 PDF 改动造成的构建失败。弱引用检查只证明非视觉成员/状态锚点所有权与活动图表强制 GC 下的选择稳定；关闭原生窗口后的回收没有据此取得资格，继续由长稳专项处理。

正式候选 v2 的 Windows 完整回归发现既有 Analysis 生命周期用例失败：自定义构建器换源后，同一次 GetMarks 被选择刷新提前推进下一帧，实际返回 95 而契约要求返回当前帧 60。修正为仅在当前帧不再失效时刷新选择，保留后续队列建立下一帧的行为；修订后开发完整回归通过 3163 / 3163，原 v2 的 3162 通过、1 失败保留。
