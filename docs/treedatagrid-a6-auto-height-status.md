## 原因与实现

在真实 Fluent + TreeDataGrid 主题、100 列、每 11 行一条换行长文本的 Windows 原生窗口中，重新启用自动行高复用即可重现：第 1 个滚动步骤，短文本第 8 行的最终 `DesiredSize.Height` 为 28，但行高缓存已记入 456；滚动 Y 因锚点修正从 701 变为 1129。两者差值均为 428，整个投影高度也增加 428。最终显示文字正确不能证明行几何正确。

| 同一步骤的路径 | 第 8 行最终 DesiredHeight | 缓存行高 | Offset.Y | 投影高度 |
| --- | ---: | ---: | ---: | ---: |
| 旧安全拆挂 | 28 | 28 | 701 | 281284 |
| 仅单元格失效的错误复用 | 28 | 456 | 1129 | 281712 |
| 本轮整条测量链失效后复用 | 28 | 28 | 701 | 281284 |

旧候选仅调用单元格 `InvalidateMeasure()`。保留父子关系时，模板内部的 Grid/Border/ContentPresenter 仍可能在第一次测量返回上一寿命的尺寸。这个临时值写入只增不减的行高缓存后，后续正确测量不会将它恢复。原来的完整拆挂使整个测量链失效，因此两条路径不同。简单 Headless 模板没有覆盖真实主题的这条缓存链。

本轮对仍在原父级内的自动行高单元格，在重新准备后，自底向上使其可视模板及内容子树的测量失效，再进入行高观测。固定行高保留原有单层失效路径。默认工厂开放自动行高的同源滚动及投影刷新复用；自定义工厂继续完整清理、脱离、Recycle/Release。没有改写测量结果、清空整表高度缓存来掩盖差异，也没有改变滚动步长、源发布、编辑提交或公开 API。

清理协议沿用上一轮：旧绑定、内容、编辑器和事件寿命同步清除；待复用宿主只保留到下一次布局，未用宿主及时脱离；换源、换工厂、换模板和卸载释放待准备宿主。工厂会话及 generation 检查继续处理清理回调重入。
