# TreeDataGrid 开发计划

2026-10-13 后续计划已进入实际开发，见[后续完善执行计划](treedatagrid-next-development-plan.md)与[P6 执行记录](treedatagrid-p6-status.md)：可见列、外观配置、树键盘、列重排、定位、绑定与受控行移动已集成，正在完成质量测量和最终本地验证。真实平台缺口另行记录；以下保留原 P0–P7 总体规划及当时验收历史。

基线日期：2026 年 10 月 12 日。状态：P0–P5 已集成，并补齐 MVVM 数据、选择、当前单元格和编辑命令绑定，形成 `0.2.0-preview.2`。Windows 与核心模型范围内，196 项自动测试、MVVM 21 项与既有 36 项原生探针、双包独立消费通过。当前证据见 [MVVM 集成验收](mvvm-status.md)，历史见 [P4/P5](p4-p5-status.md)、[P2/P3](p2-p3-status.md)和 [P0/P1](p0-p1-status.md)。ItemsSource/XAML 内容列已提前完成；P6 其余交互和 P7 发布验收仍待实施。真实中文输入法、麒麟仍待环境验收；下文保留完整 P0–P7 规划。

目标是开发独立的 Avalonia TreeDataGrid 控件库，覆盖当前官方公开的平面表格、树形表格及相关交互能力，交付可复用的 NuGet 包、示例程序和测试。首版平台为 Windows 与 Linux，Linux 重点验收国产麒麟。麒麟的发行版、版本和 CPU 型号暂未确定，列为环境核验项。

规划启动时仓库无解决方案、源码或测试，现已建立。当前已具备选择、单元格编辑、排序过滤和树列显示交互；后续按“官方公开功能对齐 → Windows 与麒麟发布验收”推进。

**技术路线和完成标准**

- 独立实现，控件库使用自己的包名和命名空间，运行时不依赖商业 TreeDataGrid 包。
- 功能和样式使用两个独立程序集：`NT.AvaloniaControl.TreeDataGrid` 与 `NT.AvaloniaControl.TreeDataGrid.Themes`。项目名、程序集名及 NuGet 包名统一采用上述名称。核心数据逻辑作为功能程序集的内部模块组织。
- `NT.AvaloniaControl` 保留为控件系列前缀及解决方案名称；每个控件使用独立的 `NT.AvaloniaControl.<控件名>` 功能项目。后续控件与 TreeDataGrid 项目同级，默认主题按需提供独立的 `.Themes` 项目，单向引用自己的功能项目。
- 以官方 v12 文档和公开 API 为参照，在 P0 固定具体参考版本及 Avalonia 依赖版本。官方 v12 已调整列类型、绑定和数据源 API，旧版接口不能直接作为当前兼容目标。[v12 迁移说明](https://docs.avaloniaui.net/controls/data-display/structured-data/treedatagrid/breaking-changes-v12)
- 提供 XAML 列定义与代码数据源两种使用入口。公开名称和语义尽量接近参考版本，命名空间保持独立；“功能对等”“源码迁移兼容”“视觉一致”“性能表现”分别验收，二进制直接替换不作为首版目标。
- 优先验证 .NET 10 与 Avalonia 12.x 的组合，再根据麒麟可用运行时和本地依赖固定目标框架。当前桌面 Avalonia 的官方最低要求为 .NET 8，不能据此推断任意麒麟环境均可直接运行。[平台要求](https://docs.avaloniaui.net/docs/supported-platforms)
- 功能矩阵逐项记录参考版本、预期行为、实现状态、样例、测试及已知差异。文档未明确的边界通过固定版本对照验证；没有可运行参考包时，标记“按文档实现，行为未对照”，不宣称完全兼容。
- 对参考版本的需求清单通过验收后再声明功能对齐。后续上游新增功能进入下一版本范围。

**核心架构**

采用数据状态与可视容器分离的结构。树形支持从基础模型开始设计，首个 UI 原型可先展示平面数据。

```text
业务集合与模型变更
        ↓
平面或层级数据适配器
        ↓
排序、过滤、展开状态形成的可见行投影
        ↓
虚拟化行和单元格呈现、列头、冻结区域

选择、当前单元格、编辑事务通过节点身份和列身份关联上述各层
```

| 模块 | 主要职责 | 必须保持的约束 |
| --- | --- | --- |
| 数据适配 | 平面和树集合，属性变更，Add/Remove/Move/Replace/Reset | 替换 Source 或卸载控件后释放订阅；UI 变更遵守线程约定 |
| 节点身份和视图索引 | 节点身份、源 IndexPath、视图行号之间的映射 | 排序、过滤和移动不能通过旧行号误操作数据；同一模型出现多次时区分节点实例 |
| 列和绑定 | 取值、写值、格式化、比较器和列身份 | 纯数据逻辑与 Avalonia Binding、DataTemplate 适配分离 |
| 选择和编辑 | 选择锚点、当前单元格、提交、取消、验证 | 状态独立于被回收的行控件；编辑目标始终由身份确定 |
| 布局和虚拟化 | 列宽、行高、视口、冻结区域、滚动锚点 | 大数据量不创建全部行控件；宽度测量有明确策略 |
| 输入和状态 | 鼠标、键盘、IME、焦点、拖放和无障碍 | UI 不依赖 Windows 专用行为；通过公开属性和伪类暴露视觉状态 |
| 样式和模板 | 默认模板、颜色、字体、间距和亮暗主题 | 位于独立样式程序集，通过公开的模板契约使用功能控件 |

排序和过滤主要改变视图；自动拖行根据明确的数据源能力修改集合。无法修改的集合必须给出一致的禁用行为。冻结区域和可变行高的接口在 P1/P2 设计，避免 P6 再重构布局。

**功能和样式两个程序集**

| 程序集 | 内容 | 依赖规则 |
| --- | --- | --- |
| `NT.AvaloniaControl.TreeDataGrid.dll` | 数据源、列类型、树索引、选择和编辑状态、排序过滤、虚拟化布局、控件与 Presenter、输入处理、事件、无障碍及模板契约 | 依赖 Avalonia 基础能力；不引用样式程序集 |
| `NT.AvaloniaControl.TreeDataGrid.Themes.dll` | AXAML 样式、ControlTheme、ControlTemplate、资源字典、颜色、字体、间距、图标及亮暗主题 | 单向引用功能程序集；不实现数据操作、选择或编辑规则 |

应用引用功能程序集，并显式加载样式程序集中的资源。两个程序集可配套发布为同版本 NuGet 包，样式包声明兼容的功能包版本。应用也可以只引用功能包并提供自己的模板。

依赖方向为：`应用 → 样式程序集 → 功能程序集 → Avalonia`；应用可以直接使用功能程序集中的公开类型。功能程序集不硬编码到样式程序集的资源地址。

功能侧通过属性、伪类、模板部件和事件提供稳定的样式契约，P1 固定必需与可选的模板部件以及缺失时的处理。视觉资源全部由样式侧提供；换肤保持数据源、选择、展开状态与已提交数据不变，活动编辑会话遵循统一的保留或结束策略。布局算法和虚拟化留在功能侧，模板负责组合呈现元素。

项目结构如下，TreeDataGrid 的功能和样式项目使用独立名称。各项目内的 `Core/`、`Controls/`、`Primitives/` 只归属该控件；新增控件使用同级功能项目、统一 Demo 内的独立页面及专属测试和基准目录：

```text
src/
  NT.AvaloniaControl.TreeDataGrid/          TreeDataGrid 功能程序集
    Core/                                 数据、索引、选择和编辑状态
    Controls/                             主控件、列和交互
    Primitives/                           Presenter 与虚拟化布局
    Automation/                           无障碍适配（后续阶段）
  NT.AvaloniaControl.TreeDataGrid.Themes/   TreeDataGrid 默认样式程序集
    Themes/                               模板和主题入口
    Resources/                            颜色、字体、间距及图标
  NT.AvaloniaControl.<控件名>/              后续控件的独立功能项目
  NT.AvaloniaControl.<控件名>.Themes/       按需提供的独立样式项目
samples/
  NT.AvaloniaControl.Demo/                 统一控件示例程序
    MainWindow.cs                         导航窗口及主题切换
    DemoPageCatalog.cs                    控件页面集中注册
    Navigation/                           IDemoPage 与导航契约
    Pages/
      TreeDataGrid/                       普通 / MVVM 模式与十个场景
        Mvvm/                             强类型 View / ViewModel
      <控件名>/                           后续控件页面
  TreeDataGrid.Usage/                      最小 MVVM 接入示例
tests/
  TreeDataGrid.Core.Tests/                 模型与状态测试
  TreeDataGrid.Headless.Tests/             布局与交互测试
  TreeDataGrid.Themes.Tests/               资源、模板契约与换肤测试
benchmarks/
  TreeDataGrid.Benchmarks/                 数据和呈现性能场景
docs/
  treedatagrid-development-plan.md
```

`Core/` 中的算法和状态不依赖 Avalonia 视觉对象；它是功能项目内的代码模块，不单独生成第三个产品程序集。公开 XAML 列类型、Binding/DataTemplate 适配及 Presenter 同属功能程序集。测试、示例和基准项目不计入这两个产品程序集。

统一 Demo 当前导航包含 `overview` 和 `treedatagrid`，默认打开 TreeDataGrid。页面实现 `Navigation/IDemoPage` 的 `View`、`Activate()`、`Deactivate()` 和 `Dispose()`；主窗口缓存页面实例，切换时保留状态并暂停非当前页的后台活动，关闭时统一释放。新控件在 `Pages/<控件名>/` 实现自己的页面，在 `DemoPageCatalog` 注册，并由 Demo 引用该控件独立的功能和可选主题项目。`TreeDataGrid.Usage` 继续作为独立的最小消费者示例。

**阶段计划和依赖关系**

以下为一名熟悉 C#、Avalonia 自定义控件的开发者全职投入的粗估，共 16–24 人周，包含测试和修复。阶段以验收结果推进，P0/P1 后重新估算。该范围假设目标 x64/ARM64 环境已有可用 .NET 和渲染依赖；需要运行时或原生库移植时，另行估算。多名开发者可在接口稳定后并行实现样例、主题和测试，工期不能简单按人数相除。

**并行实施安排**

最有价值的并行窗口是 P1 公共契约稳定后的 P2–P5 模块开发，同时推进样式、样例和测试。两个产品程序集可以由多条工作线协作实现，程序集数量不限制并行任务数量。

开始大规模并行前，先统一节点和列身份、源路径与视图索引转换、投影变更通知、编辑提交与视图更新顺序，以及模板部件和视觉状态契约。每项共享契约指定一位维护者；变更时同步调整使用方及契约测试。

| 并行组合 | 可以同时开展的任务 | 开始条件 | 集成验收的依赖 |
| --- | --- | --- | --- |
| P0 内部分工 | 功能/API 清单、工程骨架、Windows 与麒麟环境调查和运行探针 | 先确定两个程序集名称及候选技术版本 | 工程和探针最后使用一致的依赖版本；麒麟需实际环境 |
| P1 内部分工 | 数据身份与投影模型、虚拟化布局原型、模板契约及主题资源设计 | 对原型输入输出形成最小共同约定 | 合并形成可供后续模块使用的公共契约 |
| P2 与 P3 | 平面呈现与列布局；树投影、展开折叠和集合变化算法 | P1 身份、索引及变更通知契约稳定 | 树展开器和可见行更新接入需 P2 基础呈现可运行 |
| P4 与 P2/P3 | 独立选择模型、编辑事务、验证规则；同期开发呈现和树算法 | P1 确定节点/列身份、写回和状态接口 | 键盘、IME、焦点、回收和折叠联动需 P2/P3 实际 UI |
| P5 与 P3/P4 | 比较器、排序及过滤算法；同期开发树模型、选择和编辑 | P1 投影接口稳定，提交和视图更新的顺序已有约定 | 树排序过滤依赖 P3 集成；状态联动与 P4 共同验收 |
| P6 各模块 | 拖放合法性算法、双入口 API、无障碍、主题和自定义模板样例 | 对应的数据、控件或模板契约可用 | 完整拖放需 P3/P5 投影、P4 状态及稳定布局；冻结列和列重排共用布局模型 |
| P7 各平台及交付物 | Windows 与麒麟回归、NuGet 消费检查、使用和迁移文档 | 使用同一个候选发布版本；目标平台环境可用 | 所有必要平台和功能验收通过后才能发布 v1.0 |

`NT.AvaloniaControl.TreeDataGrid.Themes` 从 P1 模板契约稳定后即可与功能程序集并行开发：P2 提供基础模板，P3/P4 补齐树、选择和编辑状态，P6 完善亮暗主题及自定义样式示例。业务状态和布局行为由功能侧实现，主题侧使用公开属性、伪类和模板部件。

测试基础设施、数据生成器和打包脚本可从 P0/P1 开始。每条功能工作线负责自身测试，平台与质量工作负责跨模块回归和发布证据；取得麒麟环境后立即加入持续验证。

建议最多先按四条主要工作线分工：

| 工作线 | 主要范围 | 推进顺序 |
| --- | --- | --- |
| 数据与投影 | 功能程序集中的 Core 数据模块 | P1 基础 → P3 树算法 → P5 排序过滤 → P6 行移动规则 |
| 呈现与布局 | 功能程序集中的 Presenter、虚拟化及列几何计算 | P1 原型 → P2 呈现 → P6 冻结列与列重排 |
| 交互与状态 | 功能程序集中的选择、编辑、焦点和输入 | P4 状态模型 → P2/P3 UI 接入 → P5 状态联动 → P6 拖放与无障碍 |
| 样式与验证支持 | 样式程序集、示例外观、平台探针及跨模块验证 | P1 契约 → P2 基础模板 → P3–P6 状态样式 → P7 平台与发布回归 |

如果只有两名开发者或两个执行单元，先按“数据与状态”和“呈现与样式”分工，双方分别承担对应测试；每完成一个可运行功能就集成。四条工作线是任务边界，不代表四倍交付速度。

集成按三个节点推进：先把 P2 呈现与 P3 树投影接通；再联合验证 P4 编辑选择与 P5 排序过滤；最后完成 P6 拖放、冻结和列重排等组合交互，再进入 P7 完整发布验收。此前可持续开展各自的算法和契约测试。

冻结区域、列重排、命中测试、选区绘制和编辑器定位共用几何模型，由呈现与布局工作线统一维护，其他工作线通过接口使用。P1/P2 就需要验证冻结区域；P6 是补齐交互与验收阶段。行拖放的循环检测和移动规则可以提前实现，但修改源集合的最终交互必须等待排序、过滤和展开语义稳定。

原有 16–24 人周是单人工作量粗估；并行安排影响日历工期，并会增加协调和联调开销。P1 结束后按实际任务拆分、平台可用性和集成进度重估，不直接按并行人数相除。

**Windows 和麒麟验收安排**

Windows 首先使用开发机验证，再固定发布支持的最低系统版本。Linux 先建立通用构建与测试环境，麒麟最终按实际发行版、系统版本、CPU、桌面会话及运行时记录验收组合。

Avalonia 当前 Linux 默认使用 X11，12.1 起提供可选的原生 Wayland 后端。项目先验证实际系统可用的默认路径，再按需要增加原生 Wayland；输入和拖放需按选定后端分别验收。[官方平台说明](https://docs.avaloniaui.net/docs/supported-platforms)

| 核验项 | 需要记录或验证的内容 | 影响 |
| --- | --- | --- |
| 麒麟系统 | 发行版名称、版本、桌面环境、系统补丁 | 确定发布和复现环境 |
| CPU 和运行时 | 实际 CPU 架构、.NET 可用版本、发布运行标识、本地依赖 | x64 与 ARM64 分别测试；若为 LoongArch/MIPS 等，先验证工具链与渲染依赖 |
| 图形环境 | X11/Wayland、显卡和驱动、硬件及软件渲染路径 | 确定滚动、绘制和缩放的可用配置 |
| 中文输入 | 实际输入法的预编辑、候选框、提交、取消、焦点切换 | 防止 Enter 选词被误当成提交单元格 |
| 字体和缩放 | 实际中文字体、回退、100%/125%/150%/200% 缩放 | 避免文本截断、列头错位和命中位置错误 |
| 系统交互 | 剪贴板文本编辑、鼠标拖放、快捷键、屏幕阅读器 | 验证编辑器和控件状态与系统正确配合 |
| 安装与运行 | 干净环境启动、离线部署需求、依赖缺失提示 | 避免仅在开发机可运行 |

平台采集以 `cat /etc/os-release`、`uname -m`、`dotnet --info` 和桌面会话信息为起点，保留不含敏感信息的环境记录。发行版的兼容性同时取决于 .NET 与 Avalonia 原生依赖，发布时只列实际验证过的组合。

**测试和验收用例**

核心模型采用单元测试与随机操作序列测试，覆盖增删改、展开折叠、排序过滤后的不变量。Avalonia Headless 用于布局和输入路由回归；中文输入法、剪贴板、原生拖放、无障碍和驱动表现由真实操作系统验证。

| 场景 | 必须满足的结果 |
| --- | --- |
| 选中后排序、过滤、重新展开 | 选择和当前单元格按规定跟随节点身份；隐藏与恢复策略一致 |
| 编辑时滚动并回收单元格 | 不丢值、不写入其他对象、不复用旧编辑器状态 |
| 编辑值影响排序或过滤 | 明确提交顺序；视图变化后焦点和编辑状态正确 |
| 编辑验证失败或按 Esc | 源数据和错误提示符合已定义规则；取消恢复原值 |
| 中文输入中按 Enter/Esc/Tab | 区分输入法组合输入与表格导航、提交和取消 |
| 选中行被删除或 Source 被替换 | 选区、焦点、编辑器正确清理，没有旧订阅继续更新 |
| 父节点折叠时子节点正在编辑 | 按固定策略提交或取消，焦点落在可见位置 |
| Move/Replace/Reset 及同一对象多次出现 | 身份、源路径和可见索引无混淆 |
| 行拖放到后代或不可写集合 | 拒绝无效操作，不形成树循环，不破坏源集合 |
| 冻结、调宽、列重排和横向滚动组合 | 视觉、命中、选区与编辑器位置一致 |
| 模板切换、主题切换和反复加载卸载 | 没有事件重复、绑定残留、持续内存增长 |
| 只引用功能程序集并加载应用自定义模板 | 基础显示和交互可运行；功能程序集没有反向引用内置样式 |
| 替换样式程序集或覆盖主题资源 | 不重编译功能程序集即可生效；数据和交互状态按契约保持 |
| 模板遗漏必需部件或资源 | 有清晰诊断和可预测行为，不出现不受控的空引用异常 |
| 打包后的两个 NuGet 被独立项目引用 | XAML、资源、主题及公开 API 可使用；样式包的功能依赖版本正确；无开发仓库路径依赖 |

性能场景以“建议验收数据集”建立，不作为当前已达成指标：10 万平面行与 20 列、10 万总树节点的深树/宽树、100 列及冻结列、可变行高与复杂模板、连续集合更新。分别记录首屏、展开折叠、排序过滤、滚动帧耗时、内存及可视容器数量。

P1 固定基准机、操作系统、字体、窗口大小、构建模式和数据生成种子，设置首次显示和交互延迟阈值以及允许的回归幅度。Windows 与麒麟分别建立基线；百万行和稳定 60 FPS 等承诺必须有实测后再确定。仅显示少量可见节点的 10 万节点树与全部展开的树分别计量。

每个阶段的完成条件包括：对应功能样例可操作；模型和交互测试通过；新增 API 有说明；关键行为差异有记录；发布阶段没有未解决的数据写错对象、崩溃、死循环或持续资源泄漏问题。

**主要风险和处理办法**

| 风险 | 前置处理 | 影响范围 |
| --- | --- | --- |
| 麒麟运行时或图形依赖不匹配 | P0 验证最小应用；实际 CPU 确认后固定构建组合 | 阻止该平台发布，不阻止独立 Core 开发 |
| 虚拟化与 Auto 宽度、换行冲突 | P1 原型覆盖自动测量、动态行高、冻结区域；明确测量策略 | 不通过则先调整呈现架构 |
| 选择和编辑绑定到旧行号 | 使用节点与列身份，建立变更组合测试 | 数据正确性，优先级最高 |
| 大数据过滤阻塞 UI | P5 单独测量；保留过滤计算与视图应用边界 | 先满足参考行为；异步过滤作为单独设计项 |
| API 或默认值发生漂移 | 固定参考版本；变更更新功能矩阵和迁移说明 | 控制功能对齐范围 |
| 原生输入和无障碍仅在 Windows 测过 | 每阶段增加可用麒麟环境的原生验证 | 发布必须补齐真实平台证据 |
