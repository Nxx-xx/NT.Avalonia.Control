# TreeDataGrid E1 异步加载设计与受控原型

日期：2026-10-13。E1 是[后续完善计划](treedatagrid-next-development-plan.md)中的独立增强。本文件形成设计与测试原型；本轮不新增产品 loader API，不把 E1 自动纳入 P6/P7 发布门槛，也不把受控假加载器结果当作真实远端服务或完整产品验收。

## 接入边界与所有权

应用可提供异步节点加载服务；功能程序集协调身份、取消和创建线程，主题只呈现加载/错误状态。最终公共接口名称需在独立产品化阶段确认。现有 `RowExpanding` 同步加载继续可用：同步处理器先执行，已经提供孩子时无需再重复调用异步 loader。不得在同步展开回调内等待远端任务或重入展开。

拟议请求内容包括 Source 引用与接入代次、`NodeId`、模型引用、当前节点请求版本、开始时投影版本和取消令牌。结果为该次加载取得的子节点快照；远端服务层负责认证、协议、分页与传输错误，服务对象不放入主题程序集。

控件/独立协调服务拥有请求生命周期与 CTS；应用拥有显式 Source 和业务模型。页面永久释放时先停止协调器、取消请求和解除订阅，再释放应用 Source。暂时离开页面是否继续加载应成为显式选项；首个产品实现默认取消不可再展示的请求，缓存已经成功提交的数据。现有 Source 没有公开 Dispose 通知，应用直接绕过协调器释放 Source 时只能在响应校验中发现失效；产品化时必须固定这条所有权组合，不能假设实时得知外部 Dispose。

## 请求状态与合并

| 状态/动作 | 规则 |
| --- | --- |
| 未加载节点展开 | 显示展开与加载反馈，启动一次请求 |
| 同节点重复展开 | 合并到同一个在途请求，不重复调用服务或插入孩子 |
| 成功 | 创建线程验证仍为最新请求，然后一次发布已验证子集合；缓存成功状态 |
| 已成功节点再次展开 | 使用已提交孩子，不请求远端；默认保留缓存直到明确失效 |
| 失败 | 保留错误与可重试入口，不把错误当空集合成功缓存，不重复插入部分数据 |
| 重试/刷新 | 每次分配新请求版本；刷新取消旧请求，迟到旧结果不可覆盖新结果 |
| 折叠在途节点 | 移除在途注册后取消令牌；不缓存未提交结果；迟到响应忽略 |
| 节点删除 | 按 NodeId 清理请求/状态；同一模型重新出现的新 NodeId 不继承旧请求 |
| Source 替换 | 增加接入代次，取消旧 Source 全部请求并解除其订阅 |
| 协调器 Dispose | 先标失效并解除订阅，再取消请求；忽略全部迟到回调 |

取消是有效性决策，不能依赖服务一定遵守 CancellationToken。必须先移除当前请求注册，再调用 Cancel，避免同步取消回调仍被视为有效。

加载反馈与空内容区分：空源/过滤为空使用已有 `EmptyContent`；节点正在加载和失败属于节点状态，不能用空内容推断没有远端孩子。具体占位行或树单元格模板留到产品化阶段；它们不得成为可编辑/可移动业务模型或占用持久 NodeId。

## 响应校验与创建线程

后台任务只能生成结果；不能在完成线程读取 Source、行映射、模型集合或 Avalonia 控件。完成回调先经创建线程 dispatcher 入队，然后依次校验：

1. 协调器仍存活，当前 Source 与接入代次相符。
2. 节点仍存在，NodeId 对应同一模型引用，当前请求注册仍是该请求版本。
3. 该请求没有取消，节点没有因折叠而失去注册，投影不处于延迟/故障状态。
4. 校验结果快照、循环/层级/重复响应以及默认发布适配器的事务能力；发布前记录当前投影版本，发布步骤内的业务回调仍需重验身份与代次。

开始时的 `Source.Version` 用于诊断；不能简单要求完成时等于开始值：其它节点加载、排序或普通模型更新也会推进投影版本。有效性由 Source 接入代次、NodeId/模型引用和每节点请求版本共同决定。同父移动保留 NodeId 时可继续加载该节点；跨父产生新身份或删除后重新出现则拒绝旧请求。任何最终发布前后的身份校验失败都不得根据旧路径写入另一个节点。

产品完成回调不能长时间强持有已经关闭的 View、页面或控件；服务忽略取消时仍需通过弱接入句柄/生命周期注册释放视觉对象。测试辅助的存活与晚响应检查不等于该保留对象/内存验收，产品化需另测不完成请求和长期离开页面的情况。

结果发布不能使用“逐条 Add 已经部分成功，所以失败时 Clear”作为任意业务集合的回滚方案。默认实现应先验证完整快照，再通过受控子集合替换或事务适配器一次提交；应用自定义发布器承担自己的成功提交/失败前无副作用契约。已经提交的观察者异常必须与提交前失败区分，不承诺回滚任意业务 setter、订阅者或远端副作用。

## 缓存、重试与远端样例

首版缓存的是已提交的本地子节点，不新增全局模型对象缓存。缓存键为 Source 接入代次与节点身份；显式刷新才失效，失败与取消不缓存。若后续提供 TTL、分页或外部缓存，必须另行固定合并策略，不能自动把模型相等当作同一次节点出现位置。

重试清除旧错误，分配新请求版本。一个请求只提交一次；完成回调重复触发、旧版本迟到或取消后返回都无作用。网络重试退避由加载服务负责，UI 重试动作只表达用户的新请求意图，不能在失败时无限自动重启。

产品化验收需要真实远端样例，记录服务延迟、断网、错误、取消反馈、页面切换与 Dispose。受控测试只能证明生命周期与顺序决策，不能证明服务遵守取消、实际网络协议、加载指示布局、可访问性或真实平台体验。

## 本轮受控原型范围

原型位于 `tests/TreeDataGrid.Core.Tests/AsyncLoadingPrototypeTests.cs`，全部类型为测试辅助，不向产品程序集公开。它使用真实 Source/NodeId 映射、可控制完成顺序的假 loader 和手动排队的创建线程 dispatcher；业务模型使用专为测试约束的孩子集合替换。它验证请求注册、缓存、失败重试、取消与迟到响应的决定，不实现主题反馈、控件默认异步展开、通用业务集合事务或真实远端接入。

计划场景：重复展开合并及成功缓存；失败后新版本重试；折叠取消/迟到响应；完成已排队后折叠；删除后同模型重新插入；Source 替换；协调器 Dispose；旧响应晚于新响应；多个节点请求不因无关投影版本改变失效；后台完成必须先排队到创建线程才修改模型。
