日期：2026-10-27（香港时间）。承接[活动 UIA 分组归因](treedatagrid-a6-uia-attribution-status.md)。本轮先区分受控客户端引用寿命与产品退休清理，避免将客户端仍持有的 provider 引用直接判断为产品泄漏。Fluent 构建 API 不在范围内，版本仍为 `0.2.0-preview.2` / Avalonia 12.0.3 / net10.0。

本轮受控客户端的退休保留与持续增长问题已经收敛：30 分钟增强 UIA 耐久、正式实时读取/事件批次及置顶无客户端稳定性复测通过；565 项控件回归与完整本地流程通过。证据根为 `artifacts/treedatagrid-alignment/a6-uia-retirement-20261027/`。产品功能 DLL 保持 `065DE828D26F63860FAD15061B0E39A55AB9C3E39AD9C7EEF5447A40FE3DC577`，没有修改默认宿主复用、自动行高缓存、自定义工厂备用池或公共 API。

## 已确认的客户端寿命差异

原 `System.Windows.Automation.AutomationElement` 路径没有元素级公开 Dispose，调用方释放包装对象依赖其托管寿命及底层 UIA 缓存。上一轮已观察到引用计数 COM 根通过 AutomationNode、单元格 peer、模板和合成对象连接退休表格；这条根链证明保留存在，但不能单独证明是产品在没有外部引用的情况下泄漏。

本轮在**同一产品、同一新宿主**中复用原冻结客户端二进制，60 秒对照实际完成约 62 秒 / 30 轮 / 248 帧。私有内存稳态增量 **+589.07 MiB**，原 256 MiB 护栏继续失败。客户端退出、排空及完整 GC 后，关闭 provider 前该次表格、单元格、模型和源均已回收，仍有 10 个行 peer / 行宿主。这个终点没有覆盖活动期间的增长，也说明终点保留数量会随桥接缓存状态变化。

显式 COM 客户端使用 Windows SDK 的 IUIAutomation 接口，每个返回的接口指针由独立作用域所有者持有并同步 Release；缓存树、子数组、节点、条件、请求和 Value/Selection pattern 都在回复前释放。回调只借用 sender / VARIANT，不创建 RCW 或保存 borrowed 指针。客户端级 automation 对象与两个回调对象持续存活，退休时撤销当前 fixture 的订阅，最终显式释放。

严格短测同为 30 轮 / 248 帧，全部场景快照与旧客户端对照一致，私有内存增量 **+1.60 MiB**，完整独立校验通过。更早的隔离原型为 -3.13 MiB；该值只作诊断，不与正式长耐久混用。短测说明增长依赖客户端路径，尚不能据此量化所有第三方客户端/系统缓存的保留。

## 修复与独立校验

`benchmarks/TreeDataGrid.AutomationClient` 默认选择 `explicit-com`；保留 `--client-backend managed-legacy` 供归因。宿主/驱动对应参数为 `--automation-client-backend` / `-AutomationClientBackend`。`automationClientBackendVersion=1` 记录模式，不同后端不可混为同一版本性能队列。

共享协议新增 ownership version 1，独立校验要求：

- 每个请求的接口获取/释放计数严格递增且配平，临时查询引用为零。
- 回复时三个客户端所有者与两个回调对象仍存活，终结器释放次数始终为零。
- 关闭时先移除订阅，再释放客户端对象，所有显式所有者/回调对象清零；不能以旧托管 GC 回执代替显式释放。
- 完整实时 Name / Value / Selection、行列身份、视口数、进程、哈希、订阅、退休消失、事件增量及计时相关性检查全部保留。

这些计数描述客户端自己拥有的接口，并不计数 UIA 系统内部全部引用。是否仍有退休产品图由独立堆图检查，内存是否持续增长由原护栏与原始进程/堆指标检查，计数不能替代它们。

客户端显式请求 `AutomationElementMode_Full`，不是 cache-only 元素。首个原型把枚举值设成 None，实时 pattern 读取立即失败；失败原始记录留存，没有降低读取规则来通过。接口槽、GUID 与 VARIANT 布局按本机 Windows SDK 10.0.26100.0 的 UIAutomationClient.idl / .h 核对；标准接口说明见 [Microsoft IUIAutomation 文档](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/)。当前显式工具路径限定 Windows x64，其他平台不能由此推断已认证。

7 项本机所有权自检覆盖 VARIANT ABI、重复 Dispose、失败 HRESULT 返回指针、异常展开、结构/属性回调的 borrowed 参数和最终清零。原生记录73 / 自动化60 / 几何9 / 验收8，共 **150 项独立校验测试**已通过。没有在测量循环内加入宿主 GC、客户端 GC、provider 重置或模板暂拆。

## 原生验证与活动堆证据

冻结新宿主/客户端与源输入后，顺序运行正式负载；采样、堆图和完整回归都在独立进程中另行执行。

`explicit-soak-30m/` 完成 **1800.0013314 秒 / 899 轮 / 7272 请求**（另含十轮预热）。116 个资源快照交叉校验有效，无当前估计不可用或 Any 一致性告警。稳态私有内存中位数增量 **5939200 B（5.66 MiB）**、句柄 **-17**，通过原 256 MiB / 128 句柄调查护栏。测量期间没有应用层强制宿主/客户端 GC 或 provider 重置；标准运行时 GC 正常发生。

全程 9090 次外部查询，2470200 次临时接口获取与释放配平，终结器释放为 0；关闭时客户端级所有者与回调对象均清零。收到 890699 个结构事件和 21816 个属性事件，正式测量 fixture 的属性增量检查保留。

客户端退出、12 秒排空和完整 GC 后，关闭 provider 前，**899 个退休表格、1798000 个模型、1798 个源、192730 个单元格**及全部上下文/工厂/模板 presenter/列头均已回收，仍有 **10 个行 peer / 10 个行宿主**。这个有限残余明确单列，不认证 bridge 连接时全部对象为零。显式 provider 关闭后 **4036866 个跟踪退休对象全部回收**。这次原始趋势本身通过护栏，最终零保留不是用来覆盖测量期间的增长。

`explicit-performance/` 完成六场景、1500 请求 / 900 正式帧 / 1560 次外部查询，完整独立校验通过。客户端后端不同，不能将其耗时与旧托管后端拼成产品版本提速结论。
