已具备平面 / 层级数据源、ItemsSource / XAML 列、MVVM 选择与编辑命令、树展开与同步按需加载、五种列、选择与暂存编辑、排序过滤、冻结列、行列虚拟化、独立亮暗主题和统一 Demo。已有能力继续回归，不重复安排为待实现任务。

实施交接时历史证据为 Release 构建 0 警告 / 0 错误，Core 93、Headless 93、Themes 18，共 204 项测试通过；统一 Demo 的界面 / MVVM / 既有回归分别为 66 / 29 / 36 项原生窗口检查通过。历史材料位于 `artifacts/platform/unified-demo/`；[MVVM 验收](mvvm-status.md)中的 196 / 21 等数字只描述当时结果。双 NuGet 的新名称及独立消费者已验证。本轮重新执行验证，结果单独记录，不能以旧数量代替当前源码验收。

现有窗口检查使用程序化输入和离屏图像，不等同于真实中文输入法、桌面截图、屏幕阅读器或多 DPI 验收。麒麟目标发行版、架构和运行环境尚待提供。

交付结构保持以下约定：

- `NT.AvaloniaControl.TreeDataGrid` 提供功能，`NT.AvaloniaControl.TreeDataGrid.Themes` 提供可选主题，主题单向引用功能。
- 示例统一放在 `NT.AvaloniaControl.Demo/Pages/TreeDataGrid/`，新功能作为该页面内的场景；主窗口只负责导航、主题与页面生命周期。
- `TreeDataGrid.Usage` 保留最小接入示例。Core / Headless / Themes 测试、基准和独立包消费者随功能同步更新。
- 保持 NodeId / ColumnId 的身份语义，区分源路径、集合索引和显示索引；保持数据源所有权、创建线程、回调重入及暂存编辑契约。

## P6-A：第一批交互

状态：A1–A4 已按依赖顺序实现并通过自动/程序化原生检查、主题、Demo 和独立包消费。真实 IME 与物理拖动仍待人工验证；未提前调整拟议版本。

### A1：列显隐和统一可见列映射

- 增加列可见性入口，拟议为 `TreeDataGridColumn.IsVisible`，默认 `true`。隐藏保留 ColumnId、宽度和集合顺序，恢复时不创建新列身份。
- `FrozenColumnCount` 表示前 N 个可见列，实际冻结数不超过可见列数；冻结区域、滚动区域与命中测试共用同一映射。
- 隐藏当前列时按右侧邻近可见列、再左侧的顺序迁移当前单元格；取消该列编辑且不写模型。行选择保持，单元格选区按可见列收敛；全部隐藏时清空当前单元格，恢复后按明确定义的规则重新定位。
- 所有新旧显示入口都使用可见列映射，包含列头、单元格、宽度计算、横向滚动、BringIntoView、搜索和无障碍索引。

验收：冻结列隐藏 / 恢复、全部隐藏、隐藏当前列与编辑列、横向滚动、可变行高、选区收敛、Source / ItemsSource 两入口均正确；列集合与身份不因显隐而重建。

### A2：网格线与空内容配置

- 增加拟议 `GridLinesVisibility`：None / Horizontal / Vertical / All，默认保持当前水平及垂直边框。
- 提供空内容与模板入口，拟议为 `EmptyContent` / `EmptyContentTemplate`，默认保持“暂无数据”。空源、筛选为空和加载状态语义分开定义。
- 通过主题和模板绑定呈现，不在功能侧写死外观，不用强制本地值覆盖应用自定义 CellTheme。

验收：四种网格线模式、亮暗主题、冻结边界、空源 / 筛选为空 / 重新出现数据一致；只引用功能包并提供自定义模板的消费者继续可用。

### A3：树键盘操作、真实高度翻页

- 当前位于层级列且无编辑 / IME 预编辑时，普通 Right 展开节点，已展开则进入首个可见子节点；普通 Left 折叠节点，已折叠或叶节点则移动到父节点。
- 其它列的左右移动与修饰键选区操作沿用已有网格导航。模板内 TextBox、按钮、TimePicker 等控件继续接收自己的输入。
- PageUp / PageDown 根据当前行真实坐标加减视口高度，通过布局定位目标；保留当前可见列，边界夹紧，超高单行时保证至少前进 / 后退一行。

验收：根 / 叶 / 折叠 / 展开 / 筛选后节点均有明确行为；固定、混合、自动行高翻页对应实际页面高度；编辑与真实输入法选词不被树导航抢走。Headless 输入路由与 Windows 人工输入法验证分别记录。

### A4：列头拖动重排

- 增加全局 / 单列许可与可取消的重排请求、完成事件。建议全局默认关闭，单列默认允许；最终名称和默认值在 C1 固定。
- 支持拖动阈值、插入标记、滚动区域边缘自动滚动、Esc / 指针捕获丢失取消。拖动与排序点击、调宽 Thumb 相互隔离。
- 首版允许冻结区内部、滚动区内部重排；用户跨冻结边界落点无效。实际提交使用原 `Columns.Move`，包含隐藏列时正确映射集合位置。
- 拖动途中列集合 / Source / 模板变化时校验目标和操作版本，失效则取消，不能用陈旧索引移动其它列。

验收：拖动不触发排序或调宽；ColumnId、宽度、当前项和编辑会话跟随原列。矩形选区若因顺序变化不再连续，按既有规则收敛；冻结 / 显隐 / 横向虚拟化 / 编辑 / 途中换源组合通过，并提供 Demo 可操作场景。

## P6-B：树表接入与行移动

状态：B1–B4 已完成本地实现与回归。嵌套绑定支持表、compiled XAML/typed writer、事务默认适配及应用请求路径已交付；ItemsSource 的擦除适配器默认移动仍为 Unsupported，应用通过请求处理。十四个 Demo 场景包含嵌套绑定与受控行移动。范围和限制见使用说明及 P6 契约。

| 编号 | 范围 | 实施要点 | 验收标准 |
| --- | --- | --- | --- |
| B1 | 公共定位入口 | 在控件层提供按 NodeId / 源 IndexPath 的定位能力，明确是否展开祖先、是否改变选择；不得把显示行号当源路径。 | 无效 / 被过滤路径返回明确结果，不误选其它行；展开祖先、排序过滤、冻结列和布局尚未更新的组合正确。 |
| B2 | 层级绑定与安全写回 | 优先评估嵌套模型属性路径，处理每层 INPC、集合替换、null 中间节点和退订。明确显示、转换、校验、写回的顺序；保留 Source 与 ValueGetter / ValueSetter。 | 父对象 / 子集合替换后绑定切换正确，旧对象不再更新页面；无效路径有清晰诊断，转换 / 验证失败或取消时不调用 writer。外部 writer 保持成功提交或抛错前不修改模型的契约。 |
| B3 | 编译绑定接入方案 | 使用固定 Avalonia 版本的公开 API 验证事务写回能力；必要时提供类型化 getter / setter 入口。不能将显示支持等同于任意编译绑定均可自动写回。 | 明确支持表、可写 / 只读行为与实际 compiled XAML 消费样例；未支持的自动写回保留显式 setter 路径并说明限制。任意绑定自动写回不作为 1.0 门槛。 |
| B4 | 同表行 / 树节点拖放 | 先实现请求事件与应用修改模型的路径，再通过已验证的集合适配器提供默认移动；跨父 Remove + Insert 需要事务 / 补偿契约，不能仅依据集合可写。明确 before / after / inside 落点、事件取消、自动滚动、悬停展开和失败行为。 | 同父 / 跨父移动、只读集合、重复对象的不同出现位置、循环层级、编辑校验失败、途中删节点 / 换源均正确；受支持的默认适配路径失败后不得部分移动。应用处理器须遵守自己的写入一致性契约。 |

行拖放首版在存在排序或过滤时拒绝自动移动，并给出明确反馈；应用自定义处理可通过请求事件自行映射源位置。禁止移动到自身或后代。跨父移动必须按 C3 的身份契约恢复合理的选择与焦点，不能声称旧 NodeId 在所有移动中均保持。

取消和验证失败发生在模型修改前。外部 setter / 拖放处理器负责遵守成功提交或失败前无副作用的契约；任意业务回调已经发生的副作用由应用处理。默认适配器明确区分未提交失败、补偿结果和提交后的观察者异常。编辑提交或请求回调可能改变源，开始移动前必须重新校验 Source、操作版本、节点和目标位置。

绑定扩展先提交小规模能力原型与支持表，再扩大实现。若固定版本公开 API 无法安全支持某种自动写回，不依赖 Avalonia 私有反射绕行；保留明确可用的 ValueSetter / 类型化入口。
