## 未解决的性能问题

- 散点仍未通过固定负载：Windows 8765/9000、4/5 完整进程，Linux 7972/9000、0/5 完整进程。绘图记录与同步栅格仍占用较多时间，保留全部 pending；没有降低请求量、改变 exact 画质或放宽排空门槛。
- 百万点首次可用 P95 从 Windows 1130.7928 增至 1189.5808 ms，Linux 从 1292.219544 增至 1335.665949 ms。虽然仍在线内，本轮回退尚未定位，不能登记为首次可用无回归。
- Windows 柱形记录 P95 从 25.5631 增至 30.5698 ms，raster 从 4.6559 增至 6.1514 ms；完成全部请求没有消除这两项回退。Linux 柱形计划请求到 raster P95 从 1764.480893 增至 3004.458847 ms，实际时长也增加，记录、raster 及若干请求阶段亦更慢，原因尚未定位。
- 普通折线和十万点轨道也有表中所列的记录、栅格、准备或端到端回退；散点 raster 线程分配 P95 升至两端均 87408 bytes。需要保留完整对照继续定位，不能从部分指标改善推导所有场景变快。未做正式单变量因果隔离，不将这些变化归因于某一项缓存或通知改动。

## 实现

### 场景发布与 UIA 通知

标准轴的同一已发布场景不再因每次缓存读取重复协调全部交互状态和已实现自动化节点。场景失效清除发布标记；重新发布通过场景身份和版本保护处理回调重入，避免旧发布覆盖回调期间产生的新状态。视口、绘图区、选择、当前点及动画帧仍需更新对应状态。自定义实时轴保留缓存读取时的位置协调，不能用一次发布的标记遮住其实时变换。

普通场景重建期间，已经存在的可见点可能短暂没有可查询的新场景。自动化层合并这段暂态产生的重复 Name/Value unavailable 通知，待新场景发布后通知实际值；如果 dispatcher 后台轮次到来仍未发布，则发出实际不可用状态。真正隐藏、移除、解绑和选择变化及时通知，焦点事件保留。后台通知使用弱引用，并继续经过 owner 的重入协调循环。

UIA 没有关闭；点的直接 provider 查询仍反映当下是否可用。这是通知生命周期与重复工作的优化，**不代表 Windows UIA / Linux AT-SPI 原生 selected-items 枚举桥接已经完成**。该无障碍专项继续按用户决定后置。

### 可选 Skia 圆点后端

新增独立包 `NT.AvaloniaControl.Charts.Skia`，通过 `WithChartsSkiaRendering()` 或 `ChartSkiaRenderingExtensions.Initialize()` 显式注册。Demo、Usage 和 C7 宿主在启动时接入；Core 消费者可以不依赖该模块。注册不改变软件/GPU 后端选择、源数据、采样、裁剪、命中或正式 driver 的请求循环。

Demo / Usage 的实际顺序为 `Configure → WithChartsNativeTextIsolation → WithChartsSkiaRendering → UsePlatformDetect → UI 启动`。原生字体 isolation 扩展内部同步执行 Initialize；没有在 Configure 前显式调用它。Core 的源码依赖与实测程序集引用均不含 Skia。

模块将 Avalonia 与 Avalonia.Skia **精确锁定为 12.0.3**，使用 SDK 明确声明的 unstable/private API opt-in。它不是跨 Avalonia 版本的稳定接口承诺；改变锁定版本必须重新验证。历史 Core 在入口检查中保持 no-op，允许同一保真宿主和同一模块分别加载真实 B7 库与候选库。

满足条件的密集圆点在 DrawingGroup 记录时复用原生椭圆几何，减少重复几何创建，仍逐点生成独立的公开记录包装。展开路径按原始点顺序执行填充和加宽描边两个操作；直接绘制路径复用两支当前画笔，通过锁定后端的公共 `RenderOptions` / `FillPath` getter 取得状态与路径，再逐点执行相同的两次 DrawPath。getter 的声明类型属于内部 Skia 实现，仍是需要版本限定的元数据桥接，不能视为通用公共 C# API。

这种处理没有合并点、调整绘制顺序或减少 exact 数据量，也没有改动透明混合、原描边及抗锯齿要求。减少记录对象不等于减少实际逐圆原生绘制工作，固定负载结果见前表。

直接路径要求已验证的精确后端版本、软件 surface、单位设备缩放、有限整数设备平移和环境 opacity 为 1。非整数平移、非单位缩放、skew、perspective、GPU、picture recording、空间画刷或不支持的画笔保留原有路径；元数据或动态代码不可用时也回退。所有路径与画笔准备在开始绘制前完成，已经画出部分内容后的错误不会被吞掉并重画一遍。v3 的同平台专项图覆盖整数平移守卫及相关回退，不能把这些软件栅格结果扩大为任意变换或硬件资格。

### 持续计费的几何历史

Core 记录几何和可选原生几何各有按系列维护的有界历史，以精确坐标、半径及相关描边参数识别可复用形状。只有唯一 owner 的系列可共享历史，多 owner 系列不借用某一图表的预算。普通源替换、视口变化或场景失效可以保留历史，避免反复重建相同圆形；几何不通过修改旧对象迁移到新位置。

历史采用持续存在的系列资源账本，完整容量在场景失效后仍计费，包括当前小视口回退到原始圆形命令时保留的历史。场景资源只计自身载荷，避免重复计算共享历史。容量增长、预算准入和真实驱逐相互协调；预算降低、零预算、Trim、隐藏、解绑、移除或 owner 释放会退休历史及依赖它的缓存计划。旧记录仍持有的几何引用继续有效，退休历史不能销毁仍被旧帧使用的对象。

单种历史上限为 32,768 项，容量在计划准备阶段声明；**默认 128 MiB 资源预算未提高**。历史权重继续纳入既有估算模型，在公开缓存统计中归入系列绘图字节。估算资源预算不是实际 native/GPU 内存或进程峰值测量，本轮不能用它登记峰值内存 SLA 通过。

## 画质、回归与被拒绝实验

最终 v3 在 Windows、Linux 的 Charts 全量测试均为 3256/3256 通过。两端 Demo、Usage 普通构建通过，Windows `pack-skia-v3` 通过；独立干净 NuGet 消费者的 restore/run 未执行，尚未取得完整发布或 trim/AOT 资格。新增回归覆盖通知合并、真实隐藏/解绑/选择、回调重入、自定义轴当前位置、旧帧隔离、唯一 owner、跨源/视口历史、持续计费、预算降低和真实驱逐。

每平台 232 幅专项图使用同一个最终宿主和同一个 optional module，分别加载真实 B7 归档 Core 与候选 Core。96/144 DPI 下，透明、渐变、重叠、相同 X、断点、裁剪、动态画刷、源替换、视口、整数与小数平移等样例全部字节一致。每平台另有 120 幅正式原始语料首图对照。合计 464 幅专项 + 240 幅正式首图 = 704 幅图像对照全部字节一致，像素门禁没有容差，也没有要求跨 OS 字体栅格相同。
