# P1 公共契约 v1

2026-10-12，`0.1.0-preview.1`。本契约固定 P2–P5 共享边界；完整功能 API 仍按阶段补齐。`public-api.txt` 由测试对照，新增或修改公开成员必须同时审查契约、使用方和测试。

**身份与索引**

`NodeId` 是单个模型出现位置的身份。同一对象可以在同一集合或不同父节点下出现多次，每次有不同身份。同一集合中的精确 Add/Remove/Move 通知保留存活节点身份；Replace（即使替换为同一对象）和 Reset 重新分配受影响节点身份。跨父级 remove/add 是新节点，后续拖放若要保留身份需专门事务，不可悄悄推断。

`IndexPath` 是不可变、零起始的源集合路径，根深度为 0。空路径不指向节点。`TryGetNodeId` 将路径转身份；`TryGetRow` 包括折叠后隐藏的节点；`GetViewIndex` 对隐藏或不存在的身份返回 -1。`Rows` 只包括可见节点。不得缓存旧视图行号用于编辑、选择、拖放或定位。

`ColumnId` 由列分配，程序移动列保留身份。状态模型接受列身份，但列所有者负责保证该列属于当前表格，在移除时调用 `RemoveColumn`。

**投影、通知与线程**

Source 在创建线程访问、接收集合/属性通知和释放。UI 消费的 Source 应在 Avalonia UI 线程创建。后台更新必须先调度到该线程。Source 自己不依赖 Avalonia Dispatcher。

`Version` 初始为 1。`TreeDataGridRow` 和每次 `Rows` 为不可变投影快照；`ProjectionChanged` 在全部映射和新版本提交后触发，`RemovedNodes` 为被删除身份的只读快照。扩展模块应按身份重读，而非继续使用旧 Row 的路径。批处理通知 reason=Refresh。

`DeferRefresh()` 可嵌套；scope 中订阅与内部图持续维护，公开 Rows/映射/Version 保留上一提交版本。最外 scope 结束时合并一次通知；`IsRefreshDeferred` 在活跃 scope **或通知回调已经排队未发布变更**时为 true。此时禁止开始或提交编辑，避免旧投影误写已删除对象。scope 须在创建线程释放；重复释放安全。

集合通知包含 Add/Remove/Move/Replace/Reset，属性通知会重新检查子集合。无法提供有效通知索引时宁可分配新身份，也不把旧编辑指向其他对象。非通知集合需 `Refresh()`；重复对象的无通知移动只能按出现顺序对齐，无法知道业务实际移动了哪次出现。

模型或子集合可共享，每个对象/集合只订阅一次；祖先链循环、null模型和超过256层拒绝。错误图保留上次有效快照，业务修正数据后 `Refresh()` 恢复。子选择器应返回稳定集合，且不在枚举时修改图。

通知回调中的集合/属性变更排队，当前版本交付完后统一重建；回调中禁止立即 SetExpanded。单个观察者抛错不阻止其余观察者清理状态，队列处理完再抛出异常。调用者不得依靠事件异常回滚已经发生的源集合变更。

**状态与编辑顺序**

`TreeDataGridState` 独立于回收的控件。选择在隐藏时保留，删除/Replace/Reset 后清理；当前单元格因折叠隐藏时转到最近可见祖先，目标删除后清空。活动编辑目标隐藏或删除时取消，尚未提交的值没有写入模型。

当前实现为 P4 的基础：`BeginEdit` 获取原值，`CommitEdit(value)` 先校验，再写入，再结束编辑，最后释放源投影通知并发状态通知。校验失败保持会话与错误信息且零写入；取消零写入。普通 POCO 也刷新投影。reader/validator/writer 回调内禁止重入修改状态，并在回调后复核身份，防止回调删除目标导致错写。

业务 writer 须原子完成或在未改数据前抛错；控件库无法撤销任意 setter 的外部副作用。source 通知观察者抛错时数据可能已提交。完整转换、编辑器、选择矩形和手势仍属于 P4，不能把状态 API 当作已实现 UI 编辑。

模板更换和亮暗主题切换不操作业务状态：Source、身份、展开和已提交值保持。独立状态对象及活动编辑会话可保留；P4 创建真实编辑器时需重接会话，不能把会话存到行控件。

**生命周期与依赖**

应用拥有 Source，最终负责 Dispose；控件卸载/替换 Source 时只解除自己的订阅、清理绑定与容器，不 Dispose 应用 Source。应用自己创建的 `TreeDataGridState` 也由应用 Dispose，并应早于 Source。再次挂载控件重新读取最新投影。

功能项目不依赖主题；必需模板部件、伪类和几何 API 见 [呈现契约](p1-layout.md)。主题仅组合呈现与资源，不实现源操作或选择/编辑规则。默认样式可显式加载或替换。

共享契约维护归口：数据/投影由 Core 工作线维护，列/几何/模板由呈现工作线维护，状态/写回顺序由交互工作线维护；集成负责人统一审查 `public-api.txt` 变化。破坏契约的更改不能单线合入。
