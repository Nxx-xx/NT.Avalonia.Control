# TreeDataGrid A6 自动行高自定义工厂渲染长尾

日期：2026-10-24（香港时间）。承接[自动行高缓存修复](treedatagrid-a6-auto-height-status.md)。本轮保留默认宿主复用、自定义工厂完整拆挂及回调语义，处理自动行高短行/长行切换的宿主重建开销。

结论：按视口预算保留自定义工厂的已清理备用行已交付。557 项控件回归、90 项记录/平台校验、4512 条原生几何快照及本构建 10 分钟增强耐久通过。正式同状态四进程中，自定义工厂 UI P95/P99/分配下降 18.87%/19.67%/15.31%，渲染完成 P99 下降 19.32%；默认宿主复用收益保留。本次协议内长尾调查收敛，整体 A6 与真实平台/业务预算保持开放。

## 定位与实现

上轮同状态对照的自定义工厂渲染完成 P95 为 68.3514→82.9079ms，作为开放调查保留。此次先建立单场景原生诊断，固定 10000 行、100 列、列宽 110、每 11 行一条换行长文本、同一窗口/字体/DPI，检查全部 fixture 的宿主自动化 peer 未创建；逐帧记录 GC 计数与原始相关 QPC 时间。该诊断使用独立协议，不冒充正式六场景验收。

模板跟踪排除了“同一个宿主反复更换模板”的假设：同一 cell 完整拆挂后的模板和 Grid 根实例保持相同。EventPipe 采样同时显示，测量中仍大量创建模板绑定、Border、合成对象。原因在于自动行高布局收敛及滚动时，可见行数波动；固定两个备用行不足，许多已清理宿主被丢弃，随后又创建新宿主及其模板。最终可见行数在 8～14 之间变化，收敛过程的临时需求更大。

产品改动集中在 `TreeDataGridRowsPresenter`：

- 自动行高、自定义工厂仍完整清理并脱离，Recycle 后的备用行与可见行共享一个当前视口预算；预算同时受源行数约束。未覆盖回调的默认工厂及固定行高继续原来的两个备用行。
- 视口宽度变化释放旧宽度的备用行，避免保留上个宽度的大量单元格；缩高、筛选为空及切换模式按预算收缩；换源、换工厂、换模板与卸载继续释放。
- 旧池释放先隔离批次，释放回调重入创建的新寿命不会被外层释放；Trim 时核对 generation 和当前池成员，保留已有的异常聚合与恢复行为。
- `RecycleElement=false` 继续立即丢弃。每个准备/清理/回收/释放回调及 A2 事件仍按原协议执行；没有保留自定义宿主的父级、隐藏模型订阅或跳过源发布。
