## 变更与匹配契约

以下描述已拒绝候选，当前生产文件已恢复 B8。候选的原生历史保留最多两个完整向量。每个入口包含私有投影中心、原生几何对数组及同序 LRU 节点引用；重复序列可以直接绑定已有几何数组。匹配同时核对 Factory、圆半径、描边形状、点数和原始顺序。坐标哈希之后仍逐点比较 X/Y 的 double 位模式，避免仅凭哈希或近似坐标复用。

该向量只共享几何。每个新场景的数据身份和查询映射继续由原数据快照承担，每个绘制帧仍按原画刷处理并保持 fill/outline 的原始次序。Memo 未命中时继续采用 B8 的逐点解析；没有恢复 B9 被拒绝的整批持锁路径。

完整向量命中也不是 O(1)：仍有坐标哈希、精确比较及节点访问；实际绘制仍按点进行。`VectorMemoHitCount` 和 `VectorMemoPublishCount` 记录完整向量绑定与发布，不能当作绘制完成、原生调用次数或性能资格。实际路径还需核对 `FastPaintFrameCount`、原始请求证据和图片结果。

## 所有权与 32B/slot 预算

历史只在系列满足现有保守独占条件时复用。C1 继续禁止同一系列同时属于两个 Chart；该改动没有增加跨 Chart 共享。额外 `Changed` 观察者也会使独占守卫关闭，本批使用一个真实 Chart owner 加额外观察者验证这种保守回退。

在已有持久 `CircleHistory` 账本中，构造阶段先声明完整可保留容量，绘制不扩张容量。Memo 只为 2048～16384 个点的密集场景增长预留：

| 预算项 | 逻辑估算 |
| --- | --- |
| 向量 slot 容量 | `min(32768, 2 × 历史最大密集点数)` |
| 每 slot | Point 16B + 几何对引用 8B + LRU 节点引用 8B，共 32B（当前 x64 目标） |
| Memo 固定头部 | 有向量预留时 1024B，最多两个入口 |
| 原生共享历史 | `shapeCapacity × 576 + memoHeader + vectorSlotCapacity × 32` |
| 当前原生计划 | `1024 + sharedHistoryBytes + currentCount × IntPtr.Size` |

小视口保留此前完整预留，不能通过缩小当前数组把仍存活的历史移出账本。现有场景条目扣除独立共享权重，避免重复计费；本地 128 MiB 门槛保持，新增负担必须通过原准入规则。以 10000 点、20000 个向量 slot 为例，额外逻辑预留为 641024B，即 626 KiB；这不是实测进程、原生或 GPU 内存。

Clear、预算淘汰、Trim 及系列生命周期退休会清除 Memo 入口和节点引用。旧帧只保留其已填几何数组，不持有 Memo 的节点数组；已生成几何不被该清理 Dispose，旧帧继续可用。失活历史不能被旧的空或部分填充计划重新发布。图表预算/Trim 的原生验证检查退休钩子，预算准入仍由相应 Core 回归覆盖。

## Recency 修复与失效

仅提升完整向量入口的最近使用顺序，会使底层逐点 LRU 忽略一次真实访问。本批同时保存同序节点引用，Memo 命中时在一把 History 锁内按源顺序移动节点；包括重复点在内，保持 B8 逐点访问的 recency 语义，省去再次按 key 查找和逐点进入锁。

因此 A/B/A/C 中，第二次 A 应使 A 成为最近使用的几何状态，随后 C 优先淘汰 B。再次访问 A 不应重建几何，访问已淘汰 B 则可以重建。节点数组的额外引用已包含在 32B/slot 中。

发布前检查完整路径、mutation epoch、Factory、每个节点及几何对身份。任何形状逐出、Factory 切换或 Clear 都使原 epoch 与两个 Memo 入口失效。发生逐出的当前批次可以完成自己的绘制，但保守地不发布为完整向量；后续无逐出的解析才可重新发布。不能把已移出有界历史的几何重新钉在 Memo 中。

## Record 瓶颈与本批边界

完整向量复用作用于可选 Skia 原生解析路径。Core 的 `DrawingGroup` recorder 仍逐点发出 `DrawGeometry`，创建本次记录所需的公开绘图包装；既有圆几何历史减少几何重建，但没有消除这些逐点命令和分配。因此 Native Memo 命中不自动降低 `recordMs`，也不能单独证明 source/prepare/record/raster/query 整条请求管线提速。

本批继续分别观察记录、受控栅格、请求到栅格、排队、分配、完成数、pending 和实际排空时长。不得将阶段 P95 相加、把两端快慢样本混合，或只用命中计数与单次短测宣布原 30 秒积压解决。图片保真、软件诊断与正式 frame/present 资格分别登记。
