# C7-03 小场景原生计划准备候选

更新日期：2026-10-27。

本轮验证小于2048点的可选 native 计划准备候选，保留原 Render、画质、数据、门槛及保守资源账本。

**候选决定：拒绝并恢复B18。** 局部创建变快、分配减少，但原30秒配对未显示稳定端到端收益：Windows小场景P95三对均上升，Linux积压仍存在且方向混合。按未改变的接纳标准拒绝候选，精确恢复两处B18产品源文件并归档候选测试。局部构造或分配指标不能替代整体负载要求。

没有接纳新的产品绘制优化，散点固定负载积压仍未解决；局部构造或分配改善不能替代原计划的端到端接纳条件。

最新完整原协议性能证据仍为[接纳的B18批次](charts-c7-record-allocations.md)，双端各107进程；散点 pending Windows161/Linux1040、柱形均0。局部构造探针和六进程配对均不替换该完整正式基线；C7-03仍开放。

## 实现与契约

provider 对1..2047点返回 SmallNativeReservation，避免创建未使用的 CirclePlan、逐点 Bounds 扫描、paint 快照与factory查找；Core的native帧分支仍从2048点开始。显式 CreateForSeries 和密集绘制分支不变。

共享情况下，plan的总逻辑预留仍为1024+capacity×576+pointCount×指针大小，其中共享history本身为capacity×576；非共享plan总预留仍为1024+pointCount×576。首次小场景仍创建空history并Prepare，密集历史的完整容量在小视口期间保留；没有降低预算或改变准入/退休政策。这是逻辑账本，不能当成实测native或进程内存。活画刷、独立可变公开输出、旧帧、原始数据身份与多owner退休须继续成立。

## 验证

双端各3277项实际测试通过，含八方法/十个新增用例，覆盖1/1024/2047/2048、真实Skia factory、历史/LRU、完整预算、trim/零预算/拒绝准入/多owner/detach、旧导出与对象行身份；各232组严格保真通过。

两处候选产品源文件已精确恢复为B18，新增测试已归档并从产品树移出。Windows实际非增量重建后，再用新输出运行原生圆形专项29/29通过；此前未重建的29项结果保留，但不用于证明已执行恢复后的新二进制。


## 局部构造与原固定负载

局部provider构造/分配与原chart.Render→受控栅格是两个测量轨道。构造发生在retained绘图创建时，原record区间还包括DrawingGroup和Leaves计数，prepare不是独立构造计时。所有组合指标先按同请求相加再取P95，不相加多个P95。

局部探针使用同一已编译宿主及相同tiered-off配置，每端三对AB/BA/AB新进程；各计数预热1000次、测量10000次，输入/画刷预备在计时外，包含相同delegate/getter/checksum工作，强引用保活且不强制GC。2048为未改变路径的控制组。以下逐对报告，不池化。

## 后续录制与栅格复用可行性

当前密封DrawingGroup recorder仍逐项创建新的输出节点，没有公开adopt已构造节点的入口。Clone或DrawDrawing仍会逐项重录，不能消除这N个节点，同时必须保持公开几何输出独立可变与活画刷语义。真实SDK IL表明CreateLayer先CheckLease再CreateRenderTarget，后者构造SurfaceRenderTarget，未提供可复用DrawingGroup命令列表。其CreateDrawingContext重置matrix并应用DPI；Blit分支涉及matrix重置/恢复及SKSurface.Draw。层所有权、混合、clip、matrix和DPI的精确等价尚未证明，因此phase2/3仍受可行性阻塞，未实现、未声称同像素或提速。
