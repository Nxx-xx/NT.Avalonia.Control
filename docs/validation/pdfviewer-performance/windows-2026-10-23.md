## 诚实性声明

- 本记录为 **自身性能结果**。同机官方 A/B 对照需要合法参考宿主，当前不可得，全部对照项 `blocked-reference`；不得据此宣称"性能已对标"或"比官方快"。
- present 方法为 `composition-batch-rendered`（`RequestCompositionBatchCommitAsync` 的 `Rendered` 完成通知），`scanOutVerified=false`：**不是扫描输出/物理呈现**，`firstPagePresentedMs` 仅表示合成批渲染完成。headless 与合成批渲染均不能证明真实 FPS。
- 分位数为 nearest-rank（不插值）；样本池 < 20 时 p99 不报告。`firstScreenMs` 以 present 为准（`firstScreenBasis` 记录于 raw），`RenderAsync` 返回从未记作首屏。
- 门槛判定来源 `pdfviewer-performance-plan.md §6 工程初始门槛（待校准）`，**仅供信息参考**，不构成承诺；not-met 不视为回归失败。
- 时钟为 monotonic；`PdfPerformanceSession` 全程记录 stage span 与 milestone mark，产品代码从不写入 present mark。
- **记录缺陷声明**：run-env 与 raw 记录中的 `nativeLibrarySha256` 为 `963307405023898d887f76a54ed59eae0462e25cd6b50716cbc2be10a8a6f6ed`，经独立校验是 `runtimes/win-arm64/native/pdfium.dll`——harness 的 `FindNativeLibrarySha` 跨 RID 取首个同名文件的缺陷，不是实际加载的库。实际加载的 `runtimes/win-x64/native/pdfium.dll` SHA-256 为 `04100c03e41cac1f979e36e5e26fb860bcb5a7461f53830d3c098716624a27a9`（独立校验）。指标不受影响；缺陷已在 P3-05 修复，后续 run 按当前 RID 匹配记录。

## 门槛汇总与 not-met 说明

met：open-first-screen（p50/p95）、settleMs、search-first-hit、search-full-document、cancel-queued、cancel-native-render、closeUiMs、jump-page-uncached。

not-met（3 项，均为待校准门槛的信息性未达，不是测量失败）：

1. **jump-page-cached jumpMs p95=161.5ms（门槛 100ms）**：跳页路径含 `WaitForIdleAsync` 的 150ms settle 计时器下限（`SettleDelayDefault`），测得值结构性垫底于 ~150ms；跳页直达/缩短 settle 的优化归后续 PERF05/PERF09 调优，本轮仅记录。
2. **scroll-continuous frameIntervalMs p95=35.4ms / p99=37.6ms（门槛 20ms / 33.3ms）**：harness 帧节奏为强制 commit 采样（paced steps + CaptureFrameAsync），实测间隔受合成批提交节奏限制（p50≈32.9ms ≈ 30Hz 批节拍），不是 vsync 锁定的扫描输出帧率；`scanOutVerified=false`，不能当 FPS 读。
3. **open-close-cycles privateBytesDeltaBytes p95=24.6MiB（门槛 20MiB）**：10 个独立进程的私有字节增长离散度大（min 为负 -0.4MB，p50=8.8MB，max=24.6MB），差异含每进程基线噪声而非确定性泄漏（cacheBytes 两端 ~5.6KB 量级，关闭确已清空缓存）；门槛基线归 PERF03 校准后再定。

## 软件 / 硬件渲染拆分（G3 渲染方式分别报告）

子集 run `windows-2026-10-23-soft`（产物 `artifacts/pdfviewer/windows-2026-10-23-soft/performance/`）：同一 harness 以 `--rendering-mode software`（Win32 `RenderingMode = [Software]`）重跑 open-first-screen / scroll-continuous / jump-page-cached 各 30 迭代，90 条 raw 全 ok。该 run 的 `nativeLibrarySha256` 按修复后的 RID 匹配记录（win-x64 `04100c03…`），`rendering-mode: software` 记录于 run-env。

| metric（p50 / p95） | 默认（平台协商，主 run） | software（强制软件） |
| --- | --- | --- |
| firstScreenMs | 231.4 / 354.8 | 190.5 / 300.4 |
| firstPageSubmittedMs | 91.0 / 158.3 | 51.0 / 229.1 |
| frameIntervalMs（p50 / p95 / p99） | 32.9 / 35.4 / 37.6 | 30.5 / 33.7 / 36.0 |
| settleMs | 160.9 / 168.5 | 159.0 / 167.3 |
| jumpMs（cached） | 156.6 / 161.5 | 156.3 / 160.0 |

诚实边界：harness 记录的是**请求**的渲染模式；Avalonia 公开 API 无法查询协商后的实际后端，主 run 的「默认」在本机究竟落在 GPU 路径还是软件回退**未经验证**，不得写成「硬件渲染结果」。两种模式在本机的差异在样本噪声内（软件模式首屏 p50 甚至略快），帧节奏与跳页 settle 下限的结构性特征一致。软件模式的门槛判定：firstScreen p50/p95 met、settleMs met、jumpMs not-met、frameInterval not-met——与主 run 同一分布。
