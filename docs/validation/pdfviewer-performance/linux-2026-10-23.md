- 运行入口：`scripts/pdfviewer/benchmark.sh --run-id linux-2026-10-23`（WSL2 Ubuntu 26.04 内构建并运行）

## 诚实性声明

- **本记录是 WSL2 + WSLg 会话的补充运行，不是 Linux 实机桌面结果**（PERF18：WSL 结果只作补充）。显示为 WSLg 合成器（`DISPLAY=:0`），未使用 Xvfb；X11 软件/驱动栈为 WSLg 虚拟化路径，不能替代 `ubuntu-24.04` hosted run 或麒麟等目标实机。
- 本记录为 **自身性能结果**。同机官方 A/B 对照需要合法参考宿主，当前不可得，全部对照项 `blocked-reference`；不得据此宣称"性能已对标"或"比官方快"。
- present 方法为 `composition-batch-rendered`（`Rendered` 完成通知），`scanOutVerified=false`：**不是扫描输出/物理呈现**。
- 分位数为 nearest-rank（不插值）；样本池 < 20 时 p99 不报告。门槛判定来源 `pdfviewer-performance-plan.md §6 工程初始门槛（待校准）`，仅供信息参考；not-met 不视为回归失败。
- **记录缺陷声明**：本 run 的 `nativeLibrarySha256` 记录为 `963307405023898d887f76a54ed59eae0462e25cd6b50716cbc2be10a8a6f6ed`，经独立校验是 `runtimes/win-arm64/native/pdfium.dll`——harness 的 `FindNativeLibrarySha` 跨 RID 取首个同名文件的缺陷，不是实际加载的库。实际加载的 `runtimes/linux-x64/native/libpdfium.so` SHA-256 为 `b0361f8ba0bc6ffeb2325949a88f08b09356f46abe257ffdf846202999daa27b`（独立校验）。指标本身不受影响（linux-x64 原生解析加载 .so）；缺陷已在 P3-05 修复，后续 run 按当前 RID 匹配记录。本 run 的二进制早于 `--rendering-mode` 选项，渲染路径为平台默认（实际协商后端未查询）。

## 门槛汇总与 not-met 说明

met：open-first-screen（p50/p95）、settleMs、search-first-hit、search-full-document、cancel-queued、cancel-native-render、closeUiMs、jump-page-uncached、open-close-cycles 私有字节增量。

not-met（2 项，与 Windows 同因，均为待校准门槛的信息性未达）：

1. **jump-page-cached jumpMs p95=151.4ms（门槛 100ms）**：测得 149.98–151.52ms 几乎精确贴住 150ms settle 计时器下限（`SettleDelayDefault`），结构性垫底；跳页直达 / 缩短 settle 归后续 PERF05 / PERF09 调优。
2. **scroll-continuous frameIntervalMs p95=41.0ms / p99=49.1ms（门槛 20ms / 33.3ms）**：强制 commit 采样节奏下 WSLg 路径 p50≈21ms、尾部 40–49ms（比 Windows 默认路径 p50≈33ms 更快但更抖）；`scanOutVerified=false`，不能当 FPS 读。
