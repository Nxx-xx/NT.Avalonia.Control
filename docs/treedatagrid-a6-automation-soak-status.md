# TreeDataGrid A6 当前构建耐久与受控自动化负载

日期：2026-10-26（香港时间）。承接[自定义工厂长尾修复](treedatagrid-a6-auto-factory-tail-status.md)。本轮验证当前构建的 30 分钟增强耐久，并增加独立 Windows UI Automation 客户端。Fluent 构建 API 不在范围内，版本继续保持 `0.2.0-preview.2` / Avalonia 12.0.3 / net10.0。

本轮验证已执行完毕，**整体未通过**。560 项控件测试与完整本地流程、当前构建 1800.68 秒/900 轮增强耐久通过；默认无客户端宿主复用收益保留，两个桥接缺陷已修复。正式外部客户端读取/事件批次通过，但 603.85 秒/139 轮混合耐久的私有内存稳态增长约 3.20 GiB，超过原定护栏，判定失败。显式 provider 关闭后的跟踪对象零保留不能覆盖测量期间的增长，也不能解释为持续连接时零保留。整体 A6 保持开放。

## 产品修复与回归

功能 DLL SHA256：`A5CD845362DEE5EDDB3CEFF723B65337F467D0DBC78A9B7264EB7D244DF58A2B`。对照上一轮 `A9FD1963...`，产品改动集中在 `Automation/TreeDataGridPresenterPeers.cs`：

- 单元格 peer 原先依赖基类推断父级，而行 peer 提供的是自行构造的虚拟化子列表，没有经过基类的父级赋值。Windows 外部客户端因此在遍历行的单元格时返回 E_FAIL。现在根据当前活动行宿主解析父级；回收、换源后返回 null，避免缓存旧寿命。
- Avalonia Windows 桥接在 COM 线程探测行的 SelectionItem pattern。原条件直接读取 UI 线程所属的 SelectionUnit 属性，抛出跨线程异常并使外部客户端看不到该 pattern。现在仅在该能力探测来自外部线程时调度读取，UI 线程调用继续直接执行。

默认宿主复用、自动行高测量缓存、自定义工厂备用池及回调协议均未改变。没有产品依赖或公共 API 变更。

新增 3 项回归：默认/自定义工厂的父级关系经滚动回收及换源仍正确；外部线程探测随 Cell/Row 选择模式及退休切换正确。旧 DLL 的两个父级用例失败，修复版通过。首次异步测试夹具触发 xUnit idle-context 清理错误，改为隔离执行上下文的工作线程和有时限的 dispatcher 泵后消除；失败 XML 留存。

`regression-final/results.json` 完整通过且输入一致：Core153、Headless374、Themes33，共 **560 项**，无跳过；独立功能/主题包消费、Usage/Demo、数据/UI/40 轮回收、发布目录原生 161/29/36 项和 Gallery 通过。记录校验另有原生73、自动化33、几何9、验收8，共 **123 项**，与控件数量分开计算。

## 受控外部客户端

`benchmarks/TreeDataGrid.AutomationClient` 是独立 MTA .NET Windows Desktop 进程，不引用 Avalonia 或产品程序集。它在当前 GridId 对应的表格上订阅结构和选定属性事件，退休时移除，再为下一个 fixture 重新建立订阅，按 attach、每帧完成、retired 三个边界查询。经 Windows UIA 桥接取得的可见行、单元格、列头身份、名称、值和选择必须与宿主当前视口一致；退休 GridId 必须消失。

每个请求/回复保存不同进程 PID、QPC 时间、完整条目、独立可重算哈希及事件计数。查询位于 UI mutation/原生 render 计时之外，下一次 mutation 期间 provider 和事件订阅持续存在。它是程序化 UI 操作与外部查询交错的受控负载，不是物理输入、屏幕阅读器或任意并发客户端认证。

`automationQueryVersion=1` 明确标识 none / external-windows-uia-v1；`automationSubscriptionVersion=1` 核对每个回复绑定的订阅 GridId，并要求每个正式 soak 周期及导航编辑 fixture 的测量段产生属性事件，预热和上一 fixture 的计数不能代替。每个 fixture 的初始 peer 状态独立核验。两种状态不合并为一个性能队列。校验器拒绝缺失/重复回复、错误进程/身份/值/选择、视口数不符、计时重叠、未收到事件、退休树仍可见或关闭回执缺失等情况。

旧窗口级订阅客户端的 `controlled-v2-uia/` 已完成 1500 次原生请求、1560 次外部查询，所有视口值核对通过，但属性事件最终为 0，独立校验失败；该批次不作为正式事件负载合格证据。直接订阅当前表格的独立短试验收到 54 条属性事件，随后将客户端改为随 fixture 寿命建立/移除订阅，并增强测量段事件增量校验。受影响客户端批次使用新冻结输入和新目录复跑，保留原失败。

## 自动化保留链与关闭边界

原始无 provider 关闭的外部客户端试运行仍为失败。客户端移除事件订阅、显式终结其 UIA SafeHandle 包装对象并退出，宿主排空渲染、等待 12 秒并完整 GC 后，仍观察到末个退休表格、模板与 peer。模型、数据源、工厂和准备上下文已经回收。此结果没有被重试覆盖，也没有通过降低回收标准改为通过。

独立诊断 `retention-heap-2/` 采集 EventPipe 堆图：EventsLost=0，144282 个节点、304258 条边，声明边数一致。强引用计数根的路径包含 `ManagedObjectWrapperHolder → Avalonia.Win32.Automation.AutomationNode → NoneAutomationPeer → 模板 Border/CompositionVisual → TreeDataGridRowsPresenter → TreeDataGrid`。普通窗口/Application/dispatcher 反射遍历未找到这条原生根路径；反射结果本身不作为不存在根的证明。诊断诱发 GC，单列为归因证据，不进入正式性能分位数。

测试宿主新增显式 `--shutdown-automation-providers`，仅适用于外部客户端 soak。先完成全部负载、客户端退出、12 秒排空及完整 GC，原样保存关闭前退休快照；确认不在 SendMessage 处理中后，在当前测试进程调用 `UiaDisconnectAllProviders`，再 GC 并检查最终回收。Microsoft 将其定义为调用进程关闭前的 UIA 资源释放入口，并明确调用限制，见[官方接口说明](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcoreapi/nf-uiautomationcoreapi-uiadisconnectallproviders)。

该动作没有放入产品，也不在循环中重置 bridge、工厂或宿主。`automationShutdownVersion=1` 的独立校验核对选项、进程、HRESULT、SendMessage 状态、计时顺序、两个 GC 边界和前后不变的 tracked 总数。关闭边界试运行中，关闭前保留 1 个 Grid、1157 个 peer、2 个 presenter、15 行/150 单元格/20 列头；关闭后全部跟踪对象回收。这个边界下通过不等于持续连接时零保留，该平台缓存项仍开放。

## 30 分钟增强耐久

证据根：`artifacts/treedatagrid-alignment/a6-automation-soak-20261026/`。`soak-none-30m/` 使用隔离当前产品 DLL，实际 **1800.6789014 秒、900 轮、7280 请求**；另含 10 轮预热。默认/自定义工厂测量轮各 450，覆盖自动行高、双轴滚动、同源刷新、草稿保持/取消/一次提交、批量行移动、换源/工厂/模板/主题及列状态。

**3608454 个跟踪退休对象最终全部回收**。116 次必需 FullBlocking/进程交叉校验有效，本轮 Any 不一致和不可用当前堆估计均为 0；历史轮次告警仍保留。首末三组稳态私有内存中位数增量 **8900608 B（8.49 MiB）**，句柄增量 **-8**，未触发预先声明的 256 MiB / 128 句柄调查护栏。测量期间没有强制宿主 GC。

本轮 30 分钟属于当前 A5CD 产品构建，补足上一轮新备用池只有 10 分钟的证据；其宿主在后续可选 provider 关闭功能加入前发布，哈希和隔离目录前后校验留存。后续性能及外部客户端使用同一新宿主成对比较，产品 DLL 相同，不混淆宿主字节。

`soak-v3-uia-10m/` 完整执行 **603.8491394 秒、139 轮、1192 个原生请求、1490 次外部查询**（另含 10 轮预热），收到 **320667 条结构事件、1341 条属性事件**。每个测量周期的事件增量、当前身份/值/选择、草稿/提交/刷新与工厂寿命检查均执行；39 次遥测交叉校验有效，本轮 Any 警告和不可用当前估计均为 0。

**耐久失败**：首末三组稳态私有内存中位数增量为 **3433263104 B（约 3.20 GiB / 3274.21 MiB）**，远超预先声明的 256 MiB 调查护栏；句柄变化 -15。原始基线私有内存约 415 MiB，稳态曾超过 3 GiB。显式关闭后的私有内存仍约 1642.96 MiB，不将跟踪对象零保留等同于私有内存回到基线。

客户端退出/完整 GC 后、provider 关闭前仍保留 1 个 Grid、1340 个 peer、2 个 presenter、18 行/180 单元格/20 列头；关闭后 **774148 个跟踪对象全部回收**。该关闭边界核验成功，不能使内存护栏失败变成通过。原始 report.passed=false、进程 exit=1，独立 validated.passed=false；缺失顶层完成检查源于失败提前返回，原始请求/完成总数均为 1192。

另有 `maintained-client-60s/` 诊断：仅在外部客户端每个 fixture 退休时完整 GC，宿主测量期间仍不强制 GC。它运行 **60.97 秒/21 轮**，私有内存稳态增量仍为 **505004032 B（481.61 MiB）**，同样触发护栏，关闭后跟踪对象回收。该 pilot 是独立归因试验，不替换正式失败，也不足以将增长归因于客户端单侧包装对象积压；没有把这种清理策略放入产品或正式客户端来改写结果。

下一步先定位活动 UIA 下的宿主管理堆/native provider 保留与通知放大，结合稳态堆根、分代 GC 和事件分配区分仍存活对象、回收时机及缓存容量；修复后按原护栏复跑，同时保留默认无客户端收益。活动 UIA 的显著延迟也需同协议复测。结果汇总为 `validation-summary-final.json`，当前源码/应用一致性见 `current-input-verification-final.json`，所有原始失败与正式材料都纳入 `evidence-manifest-final.json`。

## 保留的验收范围
