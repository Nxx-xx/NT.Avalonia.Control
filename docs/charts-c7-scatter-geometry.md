# C7-03 散点几何与积压调查

更新日期：2026-10-27。

本轮完成现有 B18 数据的散点成本归因，并验证共享原生几何记录候选。候选通过 Windows、Linux 功能与保真检查，但原协议配对没有稳定收益，已拒绝并恢复四个产品源文件；候选源码、测试、失败轮次与完整证据保留。散点固定负载积压仍未解决，没有接纳新的产品绘制优化，C7-03 仍未完成。

最新完整原协议证据仍是[记录分配与柱形批次](charts-c7-record-allocations.md)：双端各107进程；散点 pending Windows161 / Linux1040，柱形均0。本轮的六进程配对诊断没有替换此正式基线，也未因拒绝候选而补做新的完整正式活动。

## 现有负载归因

对 B18 的 raw/requests、程序集与原 oracle 做只读核验，逐阶段墙钟区间及队列债务能够闭合。record 区间包含公开 DrawingGroup 记录与测试驱动的 Leaves 遍历计数，不能把整段成本都归给产品方法；记录的托管分配也仅覆盖同步 UI 线程的指定区间，不等于进程总分配或 native。请求外 due gap 与驱动、调度和其他活动有关，不能全部当成可删除的图表成本。

密集同视口请求构成主要正债务，小视口请求可偿还部分债务。未执行的计划槽没有实测成本，未填补或外推。source/prepare 只占较小份额，不能把其理想零成本上界当成实际优化收益。

## 共享原生 Fill 几何候选

密集散点尝试将已存在的不可变 Fill IGeometryImpl 交给公开 DrawGeometry，省去 Core EllipseGeometry 输入缓存，仍让 SDK 创建独立可变输出与引用活画刷。保持点数、顺序、抗锯齿、Render 调用和预算；小场景保留原分支，factory、owner、历史退休及 Pen 变化在绘制前检查。Outline 的准备工作前移，必须评估 request→controlled-raster 与 record+raster 的合计区间。

双端各3275项测试通过，包含8个新增候选用例；各232组严格图片对照通过，同机宿主、依赖和运行时相同，仅替换已确认的产品 DLL。保真和命中通过不表示固定负载通过。

独立审计直接重算原 raw 与每条 JSONL、身份和分配；恢复后四个产品源文件与接纳的 B18 精确指纹相同，候选测试从产品树移出但保存在私有归档。此前汇总器的同文件数组顺序误拒绝、临时目录权限失败和分析器 schema 错误单独保留；修复只作用于新汇总，不改原数据或门槛。

候选 source-v2 冻结闭包缺少 docs/charts-performance-budgets.json，因此不具备直接启动新正式活动的资格；本轮未使用它运行107进程正式活动。若后续候选值得正式复测，须另建包含未修改原预算的新闭包，保留旧冻结与诊断证据。

## Oval fill 独立探针

新独立探针仅把原生圆形填充命令换为同坐标 oval，保留原轮廓路径、点序和画质。Windows、Linux phase1 各123组完整 BGRA 精确比较通过，包含原始10000点生产坐标、裁剪、图层、矩阵与活画刷。简要汇总保留PNG指纹，未宣称独立解码；这仍是 owned-native 探针，未接入产品。

双端各三对 AB/BA/AB 新进程、每进程10秒 N10 诊断；同一计时二进制在每个进程先完成123组保真。每组重新准备并验证 Bounds 表，准备+10次绘制+退休成本全部计入，再除实际draw数；冷路径创建另列raw，清屏、读回、PNG与驱动记录不在该绘制计时内。不能将此数值当成原 C7 端到端请求或真实present。

## 剩余工作

下一项具体候选是核对小于2048点场景的可选 native 计划准备：当前 Core 小场景不调用 native CreateFrame，却仍构造 CirclePlan，进行 Bounds 扫描和 Pen 快照。可研究条件化或延迟准备，但必须先保持资源预留/准入、共享历史、退休与旧帧所有权语义。本项尚未实现、未验证收益、未接纳源码，不能登记为已解决积压。

共享 Fill 只减少输入几何，SDK 的公开输出包装与节点仍会产生；本轮密集 record 分配P95反而增加104B，不能声称大幅减少分配。继续定位公开记录与受控栅格成本，候选需先证明两平台稳定净收益，再考虑接入及完整原协议复测。保留公开输出独立可变、活画刷、原始数据身份及资源退休契约。

官方当前无许可，维持 blocked-reference，measurements/ratios=null。真实present、正式匹配峰值、native/GPU分量及实机资格未增加；Ubuntu实机、硬件GPU、物理触控、百万点命中尾延迟和原生UIA/AT-SPI专项按用户决定后置。
