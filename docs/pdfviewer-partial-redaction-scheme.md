# P0 字符簇与部分图像删除方案

本文件描述 `CjkClusterRedactionProbe` 与 `PartialImageRedactionProbe` 的受限可行性方案。它们位于基准工程；当前公共 `ApplyRedactionsAsync` 仍只接受完整覆盖的页面对象。实验不能直接作为任意 PDF 的生产删除器。结果见 [P0 验证记录](pdfviewer-p0-validation.md)。

## CJK 字符簇

1. 读取实际页面内容、Identity-H Type0 / CIDFontType2、ToUnicode、CIDToGID 与 `/W` 字宽；拒绝缺失映射、旋转页和未实施的文本状态。
2. 每个源 CID 是不可拆单位。按实际 Unicode 文本的扩展字素簇边界合并 CID；单 CID 对应多个 Unicode 时，再把与它相交的簇合并，直到边界稳定。不能按 UTF-16 下标删除半个代理对、组合字符或单字形的部分逻辑文本。
3. 几何选区命中簇的一部分时，实验分别验证两种显式策略：扩张到整个簇；严格拒绝该请求。生产 UI 应显示最终影响范围，不能默默删除相邻语义单位。
4. 从原始单个 packed `Tj` 内删除目标 CID，保留字形使用由原始 `/W` 推导的绝对文本矩阵输出。邻字不向左挤压，也不靠覆盖或裁剪隐藏。
5. ToUnicode 仅保留仍使用的 CID，未使用 CIDToGID 项清零；然后使用公共严格清理器完整新目录重写，丢弃旧内容流、未用对象和非页面数据。字体程序保留，它的通用 cmap / 字形轮廓不是源页面文本序列。

语料包括简体、繁体、日文组合浊点、韩文 Jamo、Ext-B、汉字加补充平面变体选择符和单字形对应多个汉字。Jamo、变体与单字形多标量案例具有明确合成的 ToUnicode，不把它们当作 OpenType 整形、真实 IVS 字形选择或任意复杂文档的通过证据。当前正例只覆盖单页水平文本、统一字号、有限 `Tm/Tj` 状态；`TJ`、竖排、RTL、复杂整形、标记内容、Form 内文字和自定义裁剪仍须单独实施。

独立验证从原始 packed `Tj`、实际 ToUnicode / 字宽重算文本和位置，用 fontTools 从实际内嵌 GID 的轮廓得到边界，并用另一套针对该语料的簇规则验证扩张。检查所有当前 xref / 解码流、实际保留操作数、邻字坐标和目标映射清理，再用 Poppler 检查目标消失及保留像素一致。它不依赖原型报告提供的预期字形框或移除列表作为唯一答案。

## 部分图像

1. 接受页面级 `q/Q/cm/Do` 中无损 DeviceRGB / DeviceGray、8 位图像。读取实际图像尺寸、样本和调用矩阵；所有受影响内容先做支持范围检查。
2. 将每个原始像素单元变换到页面，对选区矩形做多边形正面积相交判断。相交像素的全部颜色分量写为不透明白色，其他样本字节不变。
3. 为选中的一次图像调用创建私有图像资源，只改该次 `Do`；同页或跨页的其他共享调用保持原图。随后调用公共严格清理器进行资源修剪及完整重写。
4. 独占图像输出不能残留旧图像流；共享场景允许原图只为未选调用继续存在，不能把这种实例级删除说成整个文档都不再含该图像。

正例覆盖轴对齐 RGB / 灰度、90 度旋转、镜像、一般仿射和同页 / 跨页共享实例。像素单元是最小删除单位；斜边附近会保守移除与选区相交的整个像素，部分像素可能伸出选区。精确子像素边界需要另行定义重采样和画质策略。

JPEG、透明 / 遮罩、裁剪、奇异矩阵、其他位深和嵌套 Form 当前明确拒绝，且不发布成功输出。另保留白框覆盖和裁剪反例：页面可看似隐藏内容，原图样本仍能独立恢复。独立验证从实际输入图像和矩阵重算像素掩码，比较所有样本、选区外像素、未选实例、资源可达性及尾随隐藏数据，不仅比较截图。

## 生产化与平台门槛

两个原型都从不可变输入构造候选，成功后再通过已有 `RemoveAllNonPageData` 严格策略清理；该策略会移除批注、表单、附件、书签和动作等全部非页面数据。生产接入仍需统一选区、能力判断、事务、取消、Dirty、Undo、资源预算和提交前审计，不能直接把基准工程私有方法暴露为公共 API。

剩余重点为真实语料、多字体 / 编码 / 排版、`TJ` 与复杂文本状态、JPEG / ICC / 透明 / 裁剪 / 嵌套 Form、保守像素边界的用户反馈，以及内存峰值 / 取消和两平台原生验证。Windows x64 的合成原型与独立渲染通过，不代表 Ubuntu / 麒麟、官方性能或通用安全擦除验收完成；源文件、调用方内存和文件系统历史另有寿命。
