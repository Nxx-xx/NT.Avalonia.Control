# C7-03 源准备、记录与软件栅格优化

本轮沿用[上轮基线](charts-c7-performance-comparison.md)的固定负载、数据、画质和门槛。官方许可仍不可用，参考值及倍率保持 null；实机、硬件 GPU、物理触控验证继续按用户决定后置。

## 实现

- 源替换：Entry 改为值类型，引用型业务行直接复用原始身份；静态分析只跳过不可能包含通知对象的属性路径。嵌套、object/interface、多态、Nullable、结构体子对象仍保留通知观察和重绑定。
- 普通坐标图准备：Gap 模式、没有专业附加编码的折线、面积、柱形和散点使用坐标列及原始元数据列。每次映射缓存路径和实际类型的 getter，一次计算摘要；按需还原公开数据点，保留原始对象、ID、索引、类别、值、缺失值和错误行为。已有紧凑数据和专业图族继续使用各自路径。
- 绘图记录：柱形和圆点在同一保留场景内复用不可变几何，仍逐项、按原顺序记录。每系列最多 8192 项，提前预留额外的缓存估算权重；渐变及复杂画刷保留原路径。原生绘制仍使用原 DrawRectangle / DrawEllipse，没有合并或抽掉数据点。

本地资源预算仍是既有 model 1 估算，未提高 128 MiB 默认预算。新增几何按每项 256 字节加固定开销预留，懒创建后不再增长已登记权重；该模型继续排除实际原生几何/GPU 内存，不能冒充进程内存峰值门槛。

## 不变的协议

Windows x64 / Win32 与 Ubuntu 26.04 WSL2/WSLg X11/XWayland 使用同源冻结候选，.NET 10.0.13、Avalonia 12.0.3、显式软件后端、1200×650 DIP / 96 DPI。协议 SHA-256 仍为 `7E633452EA83F4A9342C68093FE597DFB0CF4B18491D21660DE70EBE73EC5463`，原工程目标、独立校验器及其 33 项测试未改门槛。

每平台五个新进程运行四轨，每轨十秒预热、三十秒固定 60Hz 请求、最多十五秒排空；保留全部 completed/failed/pending。百万点 MinMax 另有两次排除校准和一百个正式新进程。原始二进制、输入身份、命中、柱形几何、图像及时间边界继续由原独立校验器核验。

`record` 是 DrawingGroup 记录，`controlledRaster` 是同步 RTB.Render，均不等于 composition/framePipeline/present。首次可用表中的数字沿用源绑定至完整受控栅格和原始点查询结束的复合边界；数据生成、对象物化、图像编码和取证 IO 不进入该区间。三秒仍是既有名义诊断线，不能据此登记正式 render/present 通过。分位数按原 nearest-rank 算法，P99 为观察值。

## 画质、契约与诊断

两平台使用完全相同的保真宿主分别加载旧版归档库和候选库。每平台 168 幅图覆盖 96/144 DPI、折线/散点/柱形、相同 X、重叠点、NaN 断点、裁剪、透明及渐变画刷、旧记录的动态画刷、源替换与视口变化。要求逐像素完全一致，不设置容差，也不把跨 OS 字体栅格差异混入比较。

Windows 全量 Charts 测试 3207/3207，Linux 3207/3207。额外验证 INPC/嵌套观察、映射身份和不可变快照、几何记录复用、旧帧隔离、原生绘制顺序、8192 项边界和资源准入。普通映射现在拥有完整坐标列，原“不支持快速投影”的负例改为四种轴反转组合的正例，仍校验坐标位、完整几何和原始元数据。

Linux 初轮有一项分配断言失败：原计时窗口还包含 xUnit 数值断言。修正为遍历结束立即捕获分配量，保留原来的 32 次预热及 `< 1024 bytes` 门槛；复测全量通过。原失败、单项诊断、修正前后日志分别保留。Windows 修正后的同项额外通过，不以删除测试或放宽上限消除失败。

EventPipe 诊断保留原始 trace、程序集指纹和分析，报告丢失事件为 0。采样栈指向 DrawingGroup 逐图元对象构造和 Skia.DrawOval；这是包含启动、预热、正式短轨迹及查询的统计诊断，不能当作阶段精确 CPU 时间，带 trace 的时间不进入正式性能池。

两个尝试未进入生产最终路径：每帧画笔快照的短测未显示稳定收益且带来扩展后端的观察语义差异，已移除；同色填充/描边圆合并在 3072 个案例中出现像素差异，已否决。独立 PNG 解码复核：96/120/144 DPI 分别有 29532/31736/39102 个像素变化，最大通道差 115/75/80。原圆形描边、抗锯齿、重叠顺序和画质均保留。

Linux 外部回归包装器曾误把历史归档目录写为 formal-v4；全量测试、首次可用和候选画质已完成，但复制历史库时失败。错误及未使用的宿主保留，另用全新宿主从实际 formal-v2 归档完成基线对照。这不属于正式性能样本，也未覆盖原证据。

## 剩余问题

源替换/准备与百万点首次可用的本轮优化已交付，Linux 三秒名义诊断超线已解决；固定请求积压仍未全部解决，C7-03 整项不结项。

- Windows S10-S-exact：完整进程 0/5，仍有 3,786 个正式请求 pending；计划→raster P95 27,507.0195 ms。

- Windows S10-B-exact：完整进程 0/5，仍有 563 个正式请求 pending；计划→raster P95 15,827.8627 ms。

- Linux S10-S-exact：完整进程 0/5，仍有 3,455 个正式请求 pending；计划→raster P95 25,531.4515 ms。

散点 record P95 的观察值本轮没有改善：Windows 为 31.2746 → 31.8570 ms，Linux 为 32.6362 → 34.5314 ms。两轮未完成轨道的样本集合不同，不能据此单独归因；该回退继续跟踪，不能把几何复用直接登记为散点性能达标。

后续优先处理 exact 散点的逐圆原生绘制及 DrawingGroup 逐图元记录成本、柱形冷场景记录与排队，继续用当前画质和协议复测。公开记录器不能直接追加保留组，Custom 记录不受支持；需要有独立像素保真与预算验证的记录/后端方案，不能靠抽掉 exact 数据、合并改变像素或放宽排空期限通过。

官方成功编译、相同画质运行和公平倍率继续 blocked-reference；正式 framePipeline/present、实际峰值 private/native/GPU、目标 Ubuntu 22.04/24.04 实机、硬件 GPU、物理触控资格继续单列。本轮没有运行远端 CI。百万点命中尾延迟优化、原生 UIA/AT-SPI 选中项桥接继续后置；C7-04 长稳与 C7-05～06 发布/API 冻结需独立验收。
