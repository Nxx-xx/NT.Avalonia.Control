# 性能测量方法与阶段记录

固定数据种子1729，Release，无调试器，SDK10.0.401 / Avalonia12.0.3；本机实测 Windows 10.0.26200 / .NET10.0.12 / x64 / 16逻辑处理器，CPU为Intel Core i5-14400F（Windows处理器注册表查询）。受限环境读取不到的字段必须标记缺失。几何视口1200×700；原生Demo窗口1180×780 DIP、缩放1，FontSize14、系统默认字体。记录字体回退是否使用实际中文字体，自动文本往返不能代替字体截图/原生输入法验收。

执行 `dotnet run --project benchmarks/TreeDataGrid.Benchmarks -c Release -- --output artifacts/benchmarks/p2-p3.json`。程序先预热小规模平面数据，其他新路径可能包含首次JIT成本；逐场景清理GC，记录 wall time 与累计分配字节；只做诊断基线，不等同稳定吞吐量、峰值内存或帧率统计。下表保留 P1 历史结果，P2/P3 结果见后续阶段记录。

| 场景 | 原型预算 ms | 2026-10-12本机首次记录 ms |
| --- | ---: | ---: |
| 十万平面行建源 | 3000 | 112.58 |
| 十万平面行刷新 | 1500 | 133.36 |
| 十万行/100列/可变行高几何 | 500 | 4.07 |
| 一千次滚动位置命中 | 100 | 7.49 |
| 十万次身份查找 | 500 | 7.65 |
| 100001节点宽树折叠建源 | 4000 | 93.11 |
| 展开十万子节点 | 1500 | 69.44 |
| 折叠十万子节点 | 1500 | 68.00 |
| 十万节点、深度100建源 | 8000 | 216.18 |

这些预算是 P1 架构退出阈值，不是产品交互性能承诺。同机同配置在独占运行下取5轮中位数作为后续比较；耗时/分配回归超过20%且绝对增加>5ms时调查，不能用不同机器单次结果作回归结论。P7需改用稳定的统计测量、首屏/交互百分位、峰值内存和帧间隔。

行容器预算：固定行高时可视行 + 两端overscan（至多4额外行），空闲池至多2；长距离滚动后 CreatedRowCount 不应随总行数线性增长。headless用十万行滚动20次校验。原生探针首屏18行、滚动20行，确认发生复用。UI首屏记录包含主动等待350ms，尚未把真实渲染首屏耗时作为稳定产品指标。最终原生探针字体选择为Inter，平台默认Segoe UI；中文逐字形回退另验。

P1 历史性能限制：源变更 O(n) 重建并分配快照；全树提前订阅；深度路径额外成本随深度增加；每个可视行创建全部列，尚未横向虚拟化，单元格仍会重建；行高用明确委托，Auto列宽用估值。P2/P3 已加入内容测量、单元格回收和水平窗口，以及批量树操作的单次投影；全树结构维护仍为 O(n)。不能由容器数量推断百万行或60FPS。

Windows 与麒麟分别建基线；当前麒麟未验证，不能复用这组结果。

## P2/P3 五轮诊断（2026-10-12）

统一 Release 构建后，停止其他开发构建，在同机连续运行五个独立基准进程。数据与预算保持既有值，并新增宽树全部展开/折叠和深树全部展开场景；全部 60 次测量通过预算。原始五个时间值、分配值、最小值、最大值及中位数保存在 [performance-p2-p3.json](validation/performance-p2-p3.json)。

| 场景 | 中位耗时 ms | 中位累计分配 MB（十进制） |
| --- | ---: | ---: |
| 十万平面行建源 | 78.07 | 65.52 |
| 十万平面行刷新 | 106.46 | 80.36 |
| 十万行/100列/可变行高几何 | 5.83 | 0.80 |
| 一千次滚动位置命中 | 1.85 | <0.01 |
| 十万次身份查找 | 10.28 | <0.01 |
| 100001节点宽树折叠建源 | 39.01 | 57.36 |
| 展开十万子节点 | 22.00 | 43.91 |
| 折叠十万子节点 | 11.31 | 33.36 |
| 宽树全部展开、单投影 | 37.89 | 50.75 |
| 宽树全部折叠、单投影 | 42.36 | 49.80 |
| 十万节点、深度100建源 | 216.10 | 101.44 |
| 十万节点、深度100全部展开 | 109.87 | 91.59 |

与 P1 单次历史记录相比，已有场景没有同时触发“超过20%且绝对增加>5ms”的调查阈值；这不是严格的统计性能对比。建源会预先索引已加载的全树，结构变更仍重建图，批量展开与折叠只提交一次完整投影。路径快照复用和可选的绑定 occurrence 索引减少不必要分配。

原生 Windows Release 探针固定1180×780 DIP、缩放1、Inter14。10万行 × 100列、冻结2列并滚动到(7000,5000)后，实现18行、144单元格、8列头，总视觉控件720；确认行与单元格都发生复用。此数量对应本次视口，不是全尺寸固定常数。显示控件和主题的后代层次比P1丰富，不能仅凭视觉控件总数推断性能退化。行/单元格数量、列身份和内容正确性分别有回归测试。

P7仍需持续滚动帧间隔、峰值内存、GC、真实输入延迟与多DPI统计；当前原生窗口首次布局计时含350ms等待，不能当作稳定首屏指标。

## P4/P5 五轮诊断（2026-10-12）

当前命令为 `dotnet run --project benchmarks/TreeDataGrid.Benchmarks -c Release -- --output artifacts/benchmarks/p4-p5.json`。在开发构建停止后连续执行五个独立进程；18 个场景共 90 次测量全部通过预算。完整时间、分配和极值见 [performance-p4-p5.json](validation/performance-p4-p5.json)。新增场景如下：

| 场景 | 中位耗时 ms | 中位累计分配 MB（十进制） |
| --- | ---: | ---: |
| 十万平面行升序排序 | 66.02 | 45.51 |
| 十万平面行降序排序 | 67.93 | 45.51 |
| 十万已排序行过滤一半 | 72.14 | 40.08 |
| 十万行批量清除排序和过滤 | 101.98 | 126.29 |
| 十万子节点同级排序 | 62.89 | 45.51 |
| 十万子节点过滤一半 | 66.80 | 40.08 |

既有场景中，平面建源 78.43 ms、刷新 105.96 ms、宽树折叠建源 44.62 ms、深度100建源 195.61 ms。与 P2/P3 五轮中位数相比，没有场景同时触发“耗时超过20%且绝对增加>5ms”阈值。所有既有场景及分配结果均保留在原始 JSON。

这组排序使用直接模型比较委托，记录的是核心投影耗时，不包括完整列头绑定取值、输入响应和渲染。已排序数据设置过滤会重新执行同级排序。DeferRefresh 合并投影发布；配置调用仍先验证候选，批量清除的累计分配包含多次候选求值，不是峰值内存。没有引入后台或增量过滤。

本轮原生 Demo 工具栏增高，同样1180×780 DIP窗口中的可用表格视口减小；十万行×百列场景实现16行、128单元格、8列头。不能把视口改变造成的容器数降低解释为算法加速。真实输入延迟、帧间隔及麒麟基线仍待后续验收。
